# 用户选择的 Alpha101 开发案例

用户于 2026-10-01 确认使用过《101 Formulaic Alphas》，并选择它作为研究材料，原话及 PDF 摘要见 `material_confirmation.json`。这是对材料和经历的确认，不是对本仓库所有假设、经济解释和自动审核的认可。

`task.json` 从已有示例提取 Alpha #101，保留第 15 页公式和原有假设归因。数据继续为合成数据，最终市场 test 区间不参与计算。三条确定性策略各重复两次，共六次执行，只有一个研究任务、一个公式含义。本案例没有需要修复的算子别名，不预设 agent 比 fixed/normalized_fixed 更好。

```bash
.venv/bin/python -m paper_alpha suite --manifest evaluation_suites/v05/manifest.json --out runs/alpha101-manual-baseline
.venv/bin/python -m paper_alpha verify-suite runs/alpha101-manual-baseline
```

正式版本验收会保存这组记录。指标包括预声明状态、逐字引用核验、独立因子/标签/权重/汇总数值检查、报告一致性、两次复现及工具调用。未执行、失败和未覆盖项不能从分母消失。执行时间是工具流程时间，不是人工研究时间。

这篇论文已在开发流程中使用，因此不能同时作为跨论文独立保留评测。v0.4 manifest 保持历史原样，其中“个人使用未确认”描述的是当时的信息状态。真正的独立保留论文和人工标准答案仍未提供。

## 人工验收步骤

1. 用基础研究表单选择现有论文与数据，定位 PDF 第 15 页，录入公式原文 `((close - open) / ((high - low) + .001))`。
2. 建立假设，明确区分论文列出的公式与自己对经济机制的解释；所需字段为 open/high/low/close，记录适用条件。系统逐字匹配不代替这一步判断。
3. 添加同式候选，确认数据版本、时间切分和预算，保存新研究并运行。检查报告所绑定的 revision、attempt 和数据摘要。
4. 审核具体输出。需要改动时创建问题和修订，保留理由；若变更窗口、字段、方向或经济假设，修改归因，不能继续声称是未改动原式。
5. 显式批准适用的回归案例并复测；原假设发生变化时，旧案例可能不可比较，不能以新的成功运行自动关闭旧问题。

`human_review_template.json` 是待填写的表单记录模板，不会自动导入引擎或标记通过。复制到独立研究工作目录，填写 reviewer、时间和逐项理由，保留所绑定任务摘要。空值始终表示未审核。真正通过 UI 产生的审核继续走既有不可变审核与问题链路。

## 人工流程基线

先固定候选、论文、数据、时间切分和允许工具，再比较“人工手动组织输入/运行/整理报告”与工作台辅助流程。固定顺序或交替顺序，并记录重复使用同篇论文带来的学习效应。

主动操作时间只累加实际记录的开始/暂停区间；等待执行、离开工作台、审核创建到关闭的历时分别记录。记录尝试数、修改数、失败原因和任务是否完成。不补填记忆中的耗时，不把自动浏览器运行当作人工实验，不把空白模板当作人工基线结果。

当前没有人工耗时观测或语义通过率结果，也没有真实市场效果、LLM 调用成本或 RAG 优势测量。
