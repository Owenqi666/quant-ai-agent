# v0.18：受控研究执行

本模块将一个显式创建的研究任务推进到现有因子引擎的实际结果。模型提供商仍为空：草稿是路径无关的结构化数据，调度动作是固定枚举，数字由原计算与核验工具产生。

## 使用流程

1. 在现有研究的当前修订上创建执行任务，提供证据、假设、候选和原始任务预算。论文和数据身份被冻结；时间切分与引擎预算继承原修订，不接受调用方改写。
2. `validate` 核验 PDF、逐条引用、字段、完整表达式 AST、公式出处、声明归因、预热和保留区间。新增或改变的假设需注明修改/推测；自动草稿不能将新原文断言直接提升为已维护的原文定义。
3. `commit` 调用现有不可变修订入口；`submit` 调用原队列，以 `normalized_fixed` 使用经过校验的表达式。
4. 已有 worker 运行原计算工具并核验产物。`observe` 每次只读取一次实际状态，不在 HTTP 内等待或无限轮询。
5. `complete` 读取精确核验的结果，保留候选结果、结果身份和原审核；其经济解释仍为未审核。
6. 从结果建立现有“研究任务”上下文，继续真实人工评审。执行任务不写人工同意或最终测试结果。

基本界面可以逐步推进上述动作。尚未接入真实 AI；后续供应商适配只需产生同一封闭草稿/动作格式，原服务端权限保持权威。

## 数据及候选停止

缺字段、非法表达式、无验证行、引用失效、规则未决都是明确停止原因。系统保留原草稿及逐候选诊断，不替换数据字段、滚动窗口或研究假设。修正科学定义需显式创建新任务。

默认任何被阻断候选都阻止整组提交。用户显式设置 `allow_partial_execution=true` 才允许仅执行已完整校验的候选；被排除候选、原因和原表达式永久保留。在 Alpha101 示例中 Alpha#5 的字段/算子不可实现而被排除；其结果没有被编造。Alpha#6 的 `correlation` 仅经既有算子别名规范化为 `ts_corr`，记录原/接受表达式；未修改数值窗口、数据字段或经济含义。

## 预算及恢复

`max_steps` 为 1～100，`max_failures` 为 1～20，`max_seconds` 为 1～600。时间自任务创建时开始，包含用户等待、队列等待、worker 计算、核验和调度。它不是只计模型调用时间。worker 启动、运行及产物发布均受原任务截止时间约束；原引擎预算仍是另一项更小的上限。任何 caller 都不能提高已保存任务的预算。

每个动作先保存不可变请求、递增序号和原 Store 效果键，再执行效果。同一个动作键重复调用返回已保存收据；崩溃或提交回应不确定时，下一 owner 先用原键恢复原修订/运行，不能创建重复实验。已存在效果在截止时间后也可被核对、记录，随后停止授权新工作。调用失败、科学阻断和取消均保留；数据库临时不可用属于有界重试，科学阻断不被当成可以无限重试的网络错误。

预算闭合后仍允许最多一个安全取消收据，以停止已排队/正在运行的原实验。它可能使账本总记录数比 `max_steps` 多 1；这只授权停止，不授权新实验，也不补回预算。

记录限制为：创建请求 256 KiB、整个冻结任务 512 KiB、上下文 128 KiB、累计账本 16 MiB。上下文提供有界引用、算子参数数量/语义版本、基础候选、已有审核和数据身份；省略完整论文与全部行情行（包括最终测试数据），并明示省略计数。它不支持任意 Python、文件路径、HTTP 地址或动态工具名。

## 可复现演示

```bash
.venv/bin/python scripts/demo_v018.py --out artifacts/demo-v018-new
.venv/bin/python -m unittest tests.test_research_jobs -v
```

输出目录必须不存在。演示创建独立工作区，产生真实修订、运行、核验结果和 ResearchCase；另以同修订/数据/设置通过原 worker 运行固定基线，逐候选对比保存结果。输出包括原输入、上下文、执行账本、Markdown、原结果、基线及 6 个停止案例。

固定基线使用同一计算引擎，证明调度集成一致性；它不证明独立数值实现正确、真实市场表现、模型优势或节省人工时间。语义参考材料与真实模型效果另行评测。

## 开发接口

`ResearchJobs(store).create(research_id, base_revision_id, draft, budget, idempotency_key, note='', allow_partial_execution=False, method_status='resolved', unresolved_rules=None)`。

`get(id)`、`list(limit=20, offset=0, research_id=None)`、`advance(id, action, idempotency_key)`、`cancel(id, idempotency_key)`、`markdown(id)`。`advance` 返回单条 `JobStep`；`get` 返回完整 `ResearchJob`。`markdown` 对终态生成稳定导出，活动态需完成/停止后导出；活跃状态读取的 wall elapsed 是动态信息。初始请求、上下文、步骤效果键、产物和来源身份均可逐项检查。

`execution_remaining_seconds(store, run_id)` 为 worker/发布核验专用，只读验证父任务、元数据、账本完整性及独立原提交键。删掉提交步骤不会让所属运行变成无预算运行；损坏绑定使计算/发布失败。
