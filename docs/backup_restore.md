# 工作区备份与恢复

备份覆盖论文、数据版本、研究修订、每次尝试的输入与代码快照、计算结果、报告、人工审核、回归案例、回归检查及事件记录。原始工作区和历史实验文件保持不变。AI 接口不参与此过程。

这是本机单用户项目的离线维护命令。先在运行工作台的终端按 `Ctrl+C`，等待 API 和 worker 退出。独立启动的 API / worker 也需要停止。服务持有共享工作区锁；备份需要独占锁，并检查由 worker 及其计算子进程继承的锁。因此，单独终止 worker 父进程而仍有计算子进程运行时，备份仍会拒绝执行。工作区锁位于同级目录的 `.<工作区目录名>.workspace.lock`；恢复在创建目标目录前就持有该锁，防止另一个服务在恢复标记写入前初始化目标。锁文件会保留，不要手动删除，以免不同进程锁住不同的文件对象。

在项目根目录执行，以下每个目标目录都必须尚不存在；其父目录需要已存在：

```sh
mkdir -p backups
.venv/bin/python -m paper_alpha.server.backup backup --home var/workbench --out backups/workbench-2026-09-30
.venv/bin/python -m paper_alpha.server.backup verify --backup backups/workbench-2026-09-30
.venv/bin/python -m paper_alpha.server.backup restore --backup backups/workbench-2026-09-30 --home var/workbench-restored
.venv/bin/python -m paper_alpha.server.launcher --home var/workbench-restored --port 8765
```

备份目录包含 `manifest.json` 和 `files/`。清单记录源工作区、数据库版本、文件大小和 SHA-256；写完所有文件并校验后才发布清单。SQLite 的 backup API 将已提交 WAL 记录合并进独立数据库，WAL、SHM 与主要运行时锁不复制。当前接受数据库版本 1–6；恢复保留该版本，由正常工作区初始化执行有序迁移。未来数据库版本会被拒绝。

v0.4 的 schema 3 保存数据导入收据、所有验证/登记尝试、问题事件及审核来源。导入文件按服务端 ID 定位，没有新增需要重定位的绝对路径。验证子进程继承工作空间及导入锁；父进程退出但子进程存活时，维护仍会被阻止。`.dataset-locks` 中的空锁文件可随目录保留，文件本身不代表有活跃执行者。恢复后 valid 收据可继续显式登记；失去所有者的 validating/registering 标为 interrupted，保留原尝试和批准请求，需显式重试。旧内置数据标记 legacy_registration，不补造验证报告；旧审核来源迁移为 legacy_unknown。

v0.6 的 schema 4 只为审核增加可空的结构化 assessment。旧记录保持 null，不补造语义通过、审核人或主动工作时间。备份和恢复包含完整审核 JSON；服务端派生状态从保存内容重新计算。数据验证报告 v1/v2 并存，旧报告和实验文件保持历史原样。升级应先停止服务并备份，再恢复到新目录进行迁移和核验。

恢复只允许新目录：先检查完整清单及所有摘要，再复制文件，最后在恢复副本的 SQLite 中调整论文、数据、尝试输出和导出文件路径。原始引擎快照、指标、报告和审核结果摘要不改写。此前的工作区路径保存在 `settings.historical_workspace_roots`，供界面脱敏。恢复后的旧实验可以验证和下载，也能继续提交新的实验与回归检查。

为避免误覆盖，已存在目录（包括空目录）、源与目标互相嵌套、符号链接、硬链接、特殊文件、路径穿越、清单外文件以及摘要不符都会被拒绝。当前单份备份上限为 100,000 个文件和目录、20 GiB；数据库快照限时 60 秒。普通文件复制耗时取决于磁盘，但总字节数受限。不要在备份进行时通过外部工具手动改写工作区。

若进程被强制终止，未完成备份没有完整清单，不能恢复；未完成恢复保留 `.restore-incomplete`，不能作为工作区启动。命令正常捕获异常时只清理本次新建目标，原工作区和备份保留。遇到强制终止留下的目录，保留它用于排查并使用新的目标目录重试。工作台启动后，worker 会将已失去执行者的运行记录恢复为需要显式重试的状态，不自动覆盖上一次尝试。

备份清单用于检测文件损坏和意外改动，不提供来源签名或加密。应保存自己信任的备份；备份含论文、研究内容和原始路径，不应作为公开演示附件。仅复制工作区也不等于分发可安装的软件版本：依赖锁、项目源代码、构建产物与交付验收记录由项目的发布流程保存。

验证：

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_backup.py' -v
```

测试覆盖 WAL 提交记录、API / worker 锁、文件篡改、路径边界、中断清理，以及实际完成实验 → 审核 → 回归案例 → 备份 → 异地恢复 → 原结果校验 → 新实验和回归检查。数值可复现性和研究有效性由各自测试评估；备份验证本身不证明 Alpha 有效。

v0.7 schema 5 新增 `mutation_receipts`，将审核或批准的请求摘要和首次响应与业务记录原子保存。旧记录不补请求键。备份恢复包含这些收据，因此恢复后使用同键同请求仍返回原记录；浏览器本机草稿/待确认请求需由原浏览器保留，不在服务器备份中。详细语义见 [幂等契约](v07_idempotency.md)。

v0.8 schema 6 将研究创建纳入同一事务化收据机制，新增 `research_reports` 冻结总结。schema 5→6 原子迁移，不为旧研究补请求键或报告；旧收据正文保留。当前备份接受 schema 1–6，恢复保留原版本，正常初始化再有序迁移。冻结报告在创建时脱敏，恢复时不重新生成，因此同一报告 JSON/Markdown 字节保持不变。升级先停止旧服务，备份并恢复至新目录；原工作区继续保留。
