# v0.10 日常研究流程

本轮将常用操作整理为“确认候选 → 运行实验 → 审核结果 → 生成报告”。继续复用现有不可变修订、实验执行、人工审核和报告接口；AI 仍未启用。流程观测、实验间对比、主动工作计时和回归用例批准均为可选，不是完成日常研究的前置条件。

## 日常操作

1. 选择研究和待提交修订，点击“1 · 确认候选”，核对表达式、论文引文、归因与字段。
2. 点击“2 · 运行实验”进入原提交面板，确认执行方式和预算后提交。提交时仍冻结所选研究修订；有结果待确认的请求继续使用原幂等键恢复。
3. 完成且产物核验通过后，在结果处点“继续审核当前实验”。选择候选，如实填写审核；通用接受不代表五维研究语义已经通过。需要完整研究审核时展开分项，不要求启动计时。
4. 点“继续为当前实验生成报告”，核对页面明确列出的单个实验，再点“为当前实验生成报告”。进入报告页面不会创建记录；只有点击生成才提交。报告与高级多实验范围共用同一个恢复状态和幂等请求，未确认请求不会被新范围覆盖。

报告保存的是当时的快照。后续审核不会改写旧报告，需要时显式生成新的报告。源数据为合成数据时，报告和界面仍保持软件验证的限制，不构成市场表现、论文完整复现或模型研究优势的证据。

## 身份与有界列表

工作台分别显示待提交修订和当前实验绑定的修订。二者不同时显式提示：审核和报告跟随实验的冻结版本，新提交跟随上方所选研究版本。未选择实验时不擅自使用最近一条结果。

目录刷新使用已有有界分页。首屏之外已明确选择的研究继续保留；当前已选历史实验在实验与审核选择中作为额外一项保留，不会因刷新前 50 条而静默换成新实验。旧工作区或旧研究的迟到结果不作为当前实验的报告范围。

## 计时与可选流程观测

流程观测组件在当前工作区和研究范围内常驻，研究页、结果、审核、报告、历史目录和新建页面之间导航不终止观测会话。非观测页面保留一个紧凑的活动会话区域，可切换阶段、暂停或返回记录页面。

普通审核的主动计时位于“可选：本次审核的主动工作时间”。开始该计时后，离开审核页进入另一主导航需要先显式暂停；已结束区间保留在按冻结结果隔离的本机草稿中。存在未结束的流程观测会话时（包括暂停状态），不再显示独立审核计时开始按钮，已有结束区间仍保留并可检查。结束流程会话后恢复独立计时入口。

切换研究、工作区、关闭页面或刷新属于原有中断边界。未知结束时间不会补算；审核草稿的已结束区间可显式恢复，未结束审核区间按既有规则排除。计时不自动扣除后台等待，也不自动推导节省时间。

## 高级入口

报告页面的“高级：自选多次实验的报告范围”和“高级：比较两次实验”折叠展示，原功能、字段和操作仍保留。来源、配置和调试 JSON 延续现有折叠入口，数值只取工具保存结果，不由前端重新计算或补造。

## 验证范围

- `dailyWorkflow.test.ts`：有界窗口保留选中身份、拒绝迟到或跨研究实验、显式单实验报告范围、历史结果与当前修订区分。
- `daily-workflow.spec.ts`：Chrome 中完成四步链路；不启动流程观测、不记录主动时间；使用 automation 审核声明；故障注入已提交但响应丢失，重试保持原实验和请求键；验证独立计时必须暂停、观测常驻和已有审核区间保留。
- `insights.spec.ts`、`research-quality.spec.ts`、`recovery.spec.ts`：保持既有比较、不可变报告、审核目标绑定与恢复断言，只显式打开新增的可选折叠入口。

以上为自动化软件验收。浏览器计时场景中的观测会话只存在于测试工作区本机草稿，不保存为人工观测；审核仍声明 automation，不产生人工耗时或完成率成果数字。执行结果以实际验收产物为准。
