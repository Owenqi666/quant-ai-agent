# v0.19：精确观察行复用与时间保护

## 已支持的范围

已有日频因子引擎仍只接受 `data_kind=synthetic` 的完整 OHLCV 网格。v0.19 在原 CSV 字节保护之上增加观察行复用检测，使合法的文件表示变化不释放已有测试区间。它不认证真实市场来源，不提供最终测试运行或解锁接口。

使用原 `load_market` 的解析结果，对每一条 `date × asset` 的五个原始 OHLCV 字段按固定顺序生成摘要。float64 使用 `float.hex()` 精确表示，不使用误差容忍或四舍五入；资产和日期使用现有引擎接受的原键。摘要版本为 `daily-synthetic-ohlcv-float64-rows-v1`。由按日期、资产排序的行摘要生成面板摘要和索引摘要。

能识别的合法变化包括 CSV 引号、CRLF、引擎实际解析为相同值的数字表示、同一日期内的资产行排序、metadata 股票池顺序，以及裁剪、追加或资产子集中的完全相同观察行。原 loader 强制跨日期递增，系统不会为任意乱序文件排序、填缺日、修复数据或修改摘要。派生 `returns` 不进入原观察行身份：裁剪后的首行收益历史可能变化，但原 OHLCV 已经被使用。

`title`、`version`、`source` 等声明不构成保护豁免。即使这些字符串不同，相同观察行仍共享历史保护。调整方式等语义声明仍保存在原 metadata 内并参加登记/完整性绑定，软件不会因为来源名称不同就把观察行视为从未使用。

## 检查如何生效

原 `research_guard` 的字节身份和原业务 `revisions` 保持权威。新保护扩展如下：

1. 新开发前缀从数据日历第一天到 `validation.end`，与旧测试区间内的任何完全相同观察行重叠时拒绝。
2. 新测试区间复用旧开发前缀中的完全相同观察行时拒绝。
3. 按实际共享行的日期判断，不把两个文件整体连通。如果只共享开发期观察行，保留期的全部行值不同，软件不会由开发期共享行自动推断保留期等价。

每次创建修订、提交、重试和领取检查均在原事务或原领取防线内完成。拒绝回滚新的研究、修订、观察索引、绑定及收据；不会产生半个实验。原幂等返回仍优先重放，不能靠重放增加权限。

`ResearchGuard.check()` 对从未声明过研究的新登记数据提供只读预检：临时通过原 loader 归一化并检查共享行，不写索引或保护声明。真正创建研究时，在原 Store 事务内建立持久索引并重新检查。

状态响应继续使用既有 `GuardStatus` 字段，边界包含复用相同行的相关数据集，冲突只统计当前数据在冲突日期也有完全相同行的历史冲突，或当前原字节保护的冲突。如果 A/B 的历史冲突日期不在 C 的共享观察行中，仅在其他日期各有相同行，不会将 A/B 冲突投影成 C 的冲突。状态最多显示原约定的 1000 条边界和 1000 条冲突，并显示总数及省略数。

## 存储、迁移与完整性

新增模块 `paper_alpha.server.observation_identity` 导出 `SCHEMA` 和 `seed_history(connection)`，由主程序 schema14→15 加性迁移调用。新增四张表：

| 表 | 保存内容 |
|---|---|
| `observation_identities` | 规范化版本、原 CSV/metadata/登记摘要、面板及索引摘要、行数量、创建来源和记录摘要 |
| `observation_rows` | 数据集、实际日期、原资产键、完整 OHLCV 行摘要 |
| `observation_revision_bindings` | 每个修订独立冻结的观察身份摘要、原登记摘要、任务摘要和绑定摘要 |
| `observation_unresolved` | 无法由原严格 loader 建立历史身份的数据集及原因 |

迁移不修改原业务行、Case、工具账本、报告数字或任何原文件。每个数据集使用 SQL savepoint：正常生成索引并绑定历史修订；失败仅添加 unresolved 记录，保留原记录及文件。再次调用 seed helper 对已有身份或 unresolved 不做回填，尤其不会恢复已被删除的修订绑定。

索引首次建立使用原引擎解析，后续流式核对键、完整网格行数和摘要，同时核对原 CSV、metadata 和登记摘要。独立修订绑定能识别索引及其自摘要一起被修改。尚无修订锚的旧数据首次使用前会再次对照实际引擎输入，不能以修改自摘要授予首次使用权限。

旧修订存在但其观察身份、索引或绑定被删除，不会在执行时重建后放行。损坏索引可能隐藏其他文件的共享行，因此无法确认的历史身份保守阻断新的执行范围。需要明确修复与来源审核，系统没有绕过按钮。历史原字节边界被删除或修改也继续拒绝。尚无任何业务修订、没有开发声明的数据集可以首次建立身份；这一判断以原 `revisions` 为依据，不以索引是否存在推断已使用历史。

核验最多处理 1000 个具有研究历史或共享行关联的数据集；超过时明确拒绝，不截断后放行。每个文件沿用原 loader 的 64 MiB 上限，每个网格沿用 2,000,000 单元上限；HTTP 导入仍沿用其更小的 100,000 单元限制。保护原始输入和 SQLite 权威同时被管理员整体重写不在软件的防篡改认证范围。

## 可复现例子与测试

在项目目录运行：

```sh
.venv/bin/python -m unittest tests.test_observation_identity tests.test_research_guard -v
.venv/bin/python scripts/demo_v019_lineage.py --out artifacts/my-v019-lineage-example
```

输出目录必须不存在。示例保存原研究与任务、四种新数据文件、每个拒绝请求/预检/错误、拒绝前后事务计数、合法同区间研究、索引摘要、关联保护状态、独立损坏克隆及 schema14→15 克隆迁移。完整索引保存在示例自己的 SQLite 中，原演示工作区不被损坏控制修改。所有示例均为合成数据，不运行收益实验、不调用模型、不提交人工审核。

专项测试覆盖实际 loader 编码/顺序/数值等价、裁剪、追加、资产子集、反向污染、非交叉行不整体连通、索引删除/修改及自摘要篡改、首次无锚索引篡改、旧原字节权威删除、并发和幂等、加性迁移、无效旧数据保留及备份恢复。

## 仍未覆盖

资产改名、任何 OHLCV 值变化、不同来源同值同键、部分字段相同和所有其他信息重叠没有自动科学等价判断。未识别的行不能解释成“独立研究”或“从未看过”。原测试日期是否在其他工具中看过也无法由软件证明。真实股票池、调整价格、公司行动、退市收益及授权范围仍需单源专属数据契约。

作者月度 MAT 是另一条已固定来源的诊断路径，匿名原行身份、扰动/删减及月度规则独立记录。本日频索引不会把作者面板改标成真实可交易行情，也不会补出作者缺失数据或允许论文收益复现。
