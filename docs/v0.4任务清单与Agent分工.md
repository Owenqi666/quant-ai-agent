# Paper-to-Alpha v0.4 任务清单与 Agent 分工

日期：2026-10-01  
状态：v0.4 业务实现及专项测试完成；本文为统一验收前的冻结快照。正式结果与最终勾选快照保存在新建的 `artifacts/release-v04-*/`，不得用本计划代替验收证据。
目标：完善数据接入、独立评测和审核回流，继续保持 AI 接口关闭与基础前端设计。

## 1. 本轮目标与执行顺序

按以下顺序交付，前一阶段验收通过后再合入下一阶段功能；允许在接口冻结后并行准备独立模块。

1. E：修复事件增量读取，保证长任务、断网重试和多次尝试的日志完整。
2. D：完成数据集上传、质量检查、不可变版本注册和研究绑定。这是本轮主线。
3. Q：扩展固定研究任务集及独立计算参考，明确覆盖范围和指标分母。
4. F：将审核意见、修订与复测结果串联，并提供基础汇总与筛选。
5. G：Git 与交付管理可并行准备；最终统一验收必须串行进行。

本轮完整示例：

> 导入第二份合成数据 → 查看质量报告 → 明确登记数据版本 → 创建绑定该版本的新研究 → 运行候选 → 审核结果 → 批准回归案例 → 创建修订 → 复测 → 查看问题是否得到处理。

AI、RAG、BRAIN 自动调用、自动论文检索、真实行情接入、视觉重设计、公网多用户部署均不属于本轮验收范围。现有 React/TypeScript、FastAPI、SQLite WAL 和独立 Python worker 继续使用。

## 3. 必须保持的工程约束

1. 优先复用现有计算、验证、事务、锁和快照实现；新增能力不能降低旧检查强度。
2. 既有研究、修订、尝试、审核和结果不可原地改写；新增数据不得改变旧实验的依赖。
3. 指标由确定性计算工具产生；前端和未来模型不能填写或修改计算结果。
4. 论文原结论、用户修改和模型推测继续分别归因；工程测试构造不能冒充论文结论或用户真实研究。
5. 开发只使用验证区间；市场数据的最终 test 区间保持锁定。
6. 不兼容、尚未覆盖、证据不足和执行失败必须分别表达，不能合并为“通过”。
7. 新 schema 迁移、备份支持版本、路径重定位和恢复测试必须一起交付。
8. 业务源码、共享接口和发布验收由明确负责人管理；每个文件同一阶段只有一个写入负责人。
9. 不修改旧 runs、artifacts 或日常工作空间来构造测试；使用独立测试目录和新增交付目录。
10. 公共 API 不接受客户端提供服务器文件路径；所有文件按服务端生成的 ID 定位。

### 3.1 数据版本绑定的明确决定

当前 dataset_id 位于 research，而不是 revision。v0.4 保持这一结构：

- 一个研究固定绑定一个不可变数据版本。
- 用户选择另一个数据版本时创建新研究，可以显式复制任务草稿；旧研究不改绑。
- 同一研究的新修订可修改假设、候选、预算和评估配置，继续引用原数据版本。
- 跨研究/跨数据版本的实验可并列展示，但不能自动当作兼容回归。
- 不为方便比较而放松旧回归案例的研究、数据或科学条件约束。

### 3.2 数据入口的明确决定

- 第一版接受受控合成 CSV 和配套 JSON 元信息；不接受任意 Python 数据生成代码。
- 沿用既有字段和语义：date、asset、open、high、low、close、volume；returns 由已声明规则派生。
- 元信息需要包含数据类型、版本、来源/生成方式、日期集合、资产集合、字段可用时点、价格处理方式和文件摘要。
- 原始文件按字节保存；解析后的元信息用于规范化比较；不要静默排序、补值、删行、替换字段或修正摘要。
- 数据合法与研究可评估是两层检查。登记前检查数据，创建研究/提交实验前检查字段需求、时间区间、预热长度及 min_assets。
- 沿用内容与元信息形成的数据指纹；展示标题不改变科学身份。相同内容重复登记返回已有版本，不覆盖原记录。
- 延续当前组合摘要算法，与已登记内置数据保持一致；另存原始元信息文件摘要作为上传凭证。metadata.version 只是展示标签，界面同时显示内容摘要或短 ID。

### 3.3 资源预算

以下是拟定开发上限，不是已测性能或吞吐成果；在 D-01 固定，并记录调整原因：

| 项目 | 初始约束 |
|---|---|
| 上传 CSV | 16 MiB |
| 上传元信息 | 2 MiB；严格 JSON，拒绝重复键及非有限值 |
| multipart 请求总量 | 分文件总量加有界协议开销；即使无 Content-Length 也检查 |
| 导入网格 | 不超过 100,000 个日期×资产格 |
| 单次数据验证 | 30 秒上限；有界子进程，超时终止其进程组 |
| 同时执行的数据验证 | 同一工作空间最多 1 个；并发请求不能无限创建子进程 |
| 事件分页 | 默认 200 条，最大 1,000 条 |
| 浏览器自动追赶 | 每轮页数和缓存条数显式有界；达到上限仍能加载历史 |

导入上限可以严于引擎的文件上限。限制错误需要指出具体限制；不得只修改前端而遗漏服务端入口检查。

## 4. 阶段 E：先修复事件读取

### E-01 定义事件分页与一致性契约

- [x] 保留既有事件数组接口，新增或明确版本化的分页入口，避免无提示改变旧调用方的返回类型。
- [x] 建议分页字段：run_id、items、next_cursor、has_more、high_watermark。
- [x] 游标使用数据库事件 sequence/id；它可能因其他研究插入事件而不连续。
- [x] engine_sequence 只表示单次引擎尝试中的顺序，不能作为跨 attempt 游标。
- [x] 分页结果与 high_watermark 在同一个读取快照中计算；一次追赶固定到该水位，后续轮询获取新水位。
- [x] 限制页大小，验证游标和水位范围；非法/过大的游标返回明确错误，不把空页伪装为全部完成。
- [x] 定义终态同步：观察到终态后重新取得水位并补齐；终态后新增审核事件或显式重试仍可刷新读取。

修改入口：主 agent 负责 server/api.py、server/service.py、schemas.py 和接口文档；前端 agent 消费冻结契约。

### E-02 实现前端增量消费

- [x] 提取独立事件读取 hook，按 run_id 管理游标、页状态和事件缓存。
- [x] 串行翻页，按事件 ID 去重；成功接收并合并后才能推进游标。
- [x] 断网或中间页失败后保留已经收到的事件，从原游标重试。
- [x] 切换 run 时取消旧请求，隔离迟到响应；旧 run 的数据不能进入新 run。
- [x] 同一 run 重试产生新 attempt 时继续读取数据库事件序列，保留前次尝试。
- [x] 展示正在同步、同步失败、已同步到某个快照等基础状态。
- [x] 缓存达到上限时显示已加载范围，并提供历史分页；禁止静默丢弃后继续显示“完整日志”。
- [x] 终态补齐完成后减少轮询；刷新能发现后续审核和新的尝试。

### E-03 最小回归与验收

| 编号 | 测试场景 | 必须观察到的行为 |
|---|---|---|
| E-A1 | 0、999、1,000、1,001、2,501 条事件 | 可完整分批取得，无重复、无缺尾 |
| E-A2 | 分页过程中追加事件，多个 run 的 ID 交错 | 当前水位内完整，新事件在后续追赶中出现 |
| E-A3 | A 请求未返回时切换至 B | A 的迟到响应不能污染 B |
| E-A4 | 两个 attempt 都从 engine_sequence=1 开始 | 仍保留正确的跨尝试顺序 |
| E-A5 | 中间页失败、断网重连 | 游标不跳跃，已加载内容不消失 |
| E-A6 | 状态已结束、并行事件请求读取了较早快照 | 终态后补齐最终页 |
| E-A7 | 达到缓存上限；游标超过水位 | 有明确提示及恢复/历史读取路径 |

门禁 E：以上测试通过，原始实验、取消/重试和基本浏览器流程保持正常，才合入 D 阶段前端功能。

## 5. 阶段 D：数据集注册与质量报告

### D-01 冻结数据导入契约

- [x] 定义 DatasetImport、ValidationAttempt、ValidationReport 与 RegisteredDataset 的数据结构。
- [x] 导入记录与已登记数据分开；失败导入不能进入可选数据列表。
- [x] 明确原始文件摘要、元信息摘要、验证器版本、报告摘要、错误规则码、登记目标 ID 的字段。
- [x] 验证报告保存检查项的 passed/failed/not_run、实际行数/日期数/资产数、验证代码摘要、耗时和资源限制。
- [x] 质量报告区分数据合法性和研究适配性，不把一种错误概括为另一种。
- [x] 报告明确 fail-fast、已检测错误数、非穷尽扫描与有限样例上限；loader 未提供坐标时不虚构定位，不把首个失败说成全部错误。
- [x] 数据读取、验证和报告生成放在 SQLite 写事务之外；登记时只执行短事务及受控文件发布。
- [x] 验证与登记分两步，登记请求绑定该次输入和成功报告的摘要，不能批准已被替换的文件。
- [x] 登记请求绑定 import_id、input_digest、validation_attempt_id、report_digest、idempotency_key；验证语义版本改变后要求重新验证。

拟议 API，在本任务完成时冻结并同步前端类型：

| 接口 | 职责 |
|---|---|
| POST /api/dataset-imports | 上传 CSV 与元信息，创建不可变导入收据；返回 import_id |
| POST /api/dataset-imports/{id}/validate | 启动一次有界验证；完成/中断结果持久保存 |
| GET /api/dataset-imports/{id} | 查看状态、验证尝试和质量报告摘要 |
| POST /api/dataset-imports/{id}/register | 显式确认成功验证，幂等登记不可变数据版本 |
| GET /api/datasets | 列出已登记版本；展示服务端确认的字段、日期和类型 |
| GET /api/datasets/{id} | 查看该数据版本和登记来源；不返回内部绝对路径 |

初期优先采用有界验证子进程与持久化收据，不为此引入新的分布式任务系统。若使用同步 HTTP 等待验证，客户端连接中断不等于验证取消，必须能凭 import_id 查询结果；如果首轮测量表明需要异步提交，再由主 agent 调整为持久化工作项，不能用不可恢复的临时后台协程代替。

### D-02 状态机、幂等与失败恢复

建议逻辑状态：

    uploaded → validating → valid → registering → registered
                          ↘ invalid
                          ↘ interrupted

- [x] 上传文件、输入摘要和收据一旦生成就不可改写；修改数据重新创建导入记录。
- [x] 验证尝试保存 owner、attempt_id、开始/结束时间和资源预算；旧执行者不能覆盖较新的尝试。
- [x] 重试生成新验证尝试，原失败/中断报告保留；同一幂等请求不能启动重复验证。
- [x] 同键不同请求返回冲突；相同合法输入的并发登记只能得到同一不可变数据版本。
- [x] valid 到 registered 期间重新核对文件及报告摘要；文件篡改后必须拒绝登记。
- [x] 对服务器退出、上传中断、磁盘写入失败、数据库提交失败分别定义结果与保留内容。
- [x] 保证不能查询到“数据库已登记但文件尚未发布完整”的可用版本。
- [x] registering 持久化保存已确认的登记请求；先同步并发布完整文件，再短事务创建数据版本、关联导入并提交 registered。
- [x] 文件发布后、数据库提交前中断时保留完整文件和收据；显式重试先核对摘要，再完成原批准请求，不重写已有目录，也不另造批准。
- [x] 工作空间重启不能仅凭 validating 状态判定执行者已死；需要独占验证锁/所有权证据，并考虑仍存活的子进程。
- [x] 遗留 registering 也需所有权检查和明确恢复策略；每次 Store 初始化不得清理另一个仍在运行的 API/验证任务。
- [x] incomplete 文件或未完成尝试不能混入 datasets；无自动覆盖，也不默默删除已有证据。
- [x] 正常服务、导入子进程、备份维护继续遵守工作空间租约；验证者退出前维护操作不得取得独占权限。

### D-03 复用既有校验并形成质量报告

- [x] 复用 evaluation.load_market 的解析和数据规则，不再另写一套相互矛盾的 OHLCV 校验器。
- [x] 将已有拒绝原因映射为稳定错误码和可检查的位置；必要时补充报告适配层。
- [x] 检查列名、日期格式、日期顺序、重复日期/资产键、声明网格覆盖、数值有限性、正值规则和 OHLC 边界。
- [x] 校验元信息中的 market_sha256，与上传的原始字节一致；不自动替用户修正。
- [x] 区分原始字段与派生字段，明确 returns 的计算与可用时点。
- [x] 合法数据注册不意味着任意研究配置都可运行：创建研究时校验 min_assets 不超过资产数、时间边界在日历内、所需字段存在。
- [x] 不允许跨训练/验证/测试区间读取收益标签；沿用当前延迟执行与边界剔除规则。
- [x] 新字段仍缺失时明确阻断；不把 close 当成 VWAP 或其他含义不同的替代。

### Q-03 统一基线与指标

继续比较 fixed、normalized_fixed、有界规则修复三条已有路径。它们使用相同任务、数据、科学配置和事先声明的资源预算，保留全部尝试。语义重复表达式另行统计，不能算成新增研究假设。

| 指标 | 分子/分母与边界 |
|---|---|
| 任务处理正确率 | 满足预声明状态及必要检查的任务 / 计划任务总数；未执行、超时和失败不能从分母消失 |
| 引用核验通过率 | 正确匹配的引用数 / 任务清单预声明必须核对的引用数；同时报告未检查数 |
| 假设忠实度 | 人工已审任务中的符合数 / 人工已审任务数；未审另列，不能以引用匹配替代 |
| 正例执行完成率 | 完成评估的预定义可执行候选 / 预定义可执行候选总数 |
| 负例正确处理率 | 按事先期望被拒绝/阻断的负例 / 预定义负例总数 |
| 独立数值验证覆盖率 | 已完成独立数值检查的输出 / 全部需要核验的输出；另列有适用参考但未完成的数量 |
| 数值一致率 | 参考检查通过数 / 实际执行参考检查数；同时列失败、未覆盖及检查异常 |
| 完整验证产出率 | 执行、来源、制品与必要独立数值检查全部通过的候选 / 预声明应可执行的候选 |
| 复现通过率 | 重复执行后符合声明比较规则的任务 / 预声明需要重跑的任务数；未运行另列 |
| 报告一致率 | 报告数字与保存结果一致的报告 / 预声明需要核对的报告数；缺失报告不能消失 |
| 耗时与调用数 | 按任务保存排队、执行、验证耗时及工具次数；说明样本和环境 |

研究任务与候选是不同统计单位，报告要分别给出。错误输入被正确拒绝属于工程处理正确，不计入“完成数值评估”。不可比较和不支持不能进入数值通过的分子。

人工耗时、模型调用成本、真实市场效果目前无测量材料，不填推断数字。数据来源、公式组、可比条件不一致时，不给出直接优劣结论。

AI 保持关闭时可以明确记录模型调用为 0；本地计算成本未测量，不能把没有外部 API 费用表述为总成本为零。性能对照若重复计时，先固定重复次数和顺序，报告样本数、中位数与范围；重复执行不增加独立研究任务数。
