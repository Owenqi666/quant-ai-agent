# v0.14 月度实验界面

## 使用入口

导航中的“月度实验”独立于原日度研究，不需要先建立 Alpha101 研究。首次使用时从“前往研究规则”保存规则版本，再回到月度入口选择该版本。

1. 选择已保存规则，查看版本身份、原文或项目归因、配置摘要及修改记录。
2. 设置包含首尾的 1–24 个月范围、代理成本 bps 和形成样本资产下限，确认受控数据及成本限制后提交。
3. 从月度历史查看流程状态、全部尝试和错误。可取消活动任务；已开始但失败、中断或取消的实验，可在三次尝试上限内明确重试。排队时取消而尚无 attempt 的实验不能重试，应明确新建。
4. 完成后检查实际计算状态、来源核验和独立数值参考。展开每月结果，检查形成时点、信号窗口、基线与对照权重、九格诊断、持有期标签覆盖、缺失日期和形成样本排除原因。
5. 对确切 attempt 和结果摘要填写审核，声明来源为人工或自动验收。冻结报告保存当时结果及审核，下载 JSON 和 Markdown；后续审核不改写旧报告。

## 数值与声明

MOM × ID 表示双维度分组后的低 ID 动量减高 ID 动量，不是把两个信号直接相乘。两条正式策略使用项目约定，界面不把它们称为论文原式复现。

所有数据来自服务器生成的 controlled_fixture 虚构日收益与日历。界面仅格式化已保存数值，不计算收益、差值或统计量。有效 gross、net 和 turnover 月份数分别展示；真实零值保留，null 显示“未提供”，完整路径中断后不补接。

成本、净收益、净值、回撤、波动与 Sharpe 的代理口径明确显示，不能解释为真实执行表现。completed 是任务流程状态；evaluated、partial、not_evaluable 和 blocked 是研究计算状态，二者分开显示。原文未决规则可以产生已核验的 blocked 记录，不能因此称为论文复现完成。AI 继续禁用。

## 提交恢复与读取隔离

- 创建、重试、审核和报告复用已有耐久请求恢复：发送前保存固定正文和 key，读取确认成功才发 POST。持久存储失败时不发送。
- 页面刷新后的安全重试使用冻结原请求，不使用当前表单。明确拒绝的请求可解除后修改；不确定响应和 409 保留原请求。
- 保存确认与后续目录读取分离；目录失败不会自动重发创建。清理本机记录失败时显示已保存事实，同时保留安全重试入口。
- 月度详情按工作区及实验 ID 挂载，请求另带序号及 AbortSignal；迟到响应不能覆盖另一实验或另一工作区。
- 状态轮询只调用轻量 status。初次状态与详情不一致或 change_token 改变时才读取完整详情。终态核验失败后，同一个 token 不会触发每次轮询都重复核验；用户可点击“完整核验并刷新月度结果”重试。
- 完整详情失败或核验返回 409 时清除当前缓存结果，禁止新审核和报告；原请求恢复组件仍保持可用。已冻结报告按自身摘要独立核验，已有报告身份及原报告请求可继续用于确认和下载。

本轮不保存未提交的月度表单或审核文本草稿；提交之后的原正文随待确认请求保存。切换离开前尚未提交的输入需要用户自行保留。

## 验证材料

`frontend/src/monthlyExperiments.test.ts` 覆盖范围和数值输入边界、零值与缺失显示、审核结果绑定、重试资格、独立分母及代理限制呈现。

`frontend/e2e/monthly-experiments.spec.ts` 使用自有临时工作区、随机 loopback 端口与真实 worker/API，不访问 8765 或真实工作区。场景覆盖：

- 无日度研究时，从规则进入完整月度运行、automation 审核和固定双格式下载。
- 真实 POST 已提交后注入响应丢失，刷新再确认创建、审核和报告，比较原正文及记录数量。
- 浏览器持久存储失败阻止提交。
- 迟到的另一实验详情不会覆盖当前选择；契约有效的 409 隐藏缓存指标，稳定 status 不反复读取坏详情。
- 当前详情读取失败时，已提交的报告仍可凭原请求重放并下载。

浏览器的 409 场景为明确的传输层替身，用于检查界面隐藏与恢复行为；真正文件破坏、摘要校验和旧数据库迁移由后端集成测试覆盖。所有浏览器审核均标为 automation，不是用户的人工研究结论。实际通过计数以本轮开发日志和最终统一发布验收为准。
