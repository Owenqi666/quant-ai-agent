## 实施前评估

1. 审核、批准已有耐久请求恢复；研究创建仍缺请求幂等，实验提交键仅保存在前端内存，且保存成功与目录刷新仍混在一起。修订已有乐观锁，不将其描述为静默覆盖风险。
2. 已有单次实验报告、回归检查、审核汇总；缺少两次实验的统一条件对比和指标差异视图。
3. 缺少研究级冻结总结，不能通过同一个报告标识下载一致的 JSON 与 Markdown，把证据、版本、尝试、失败、审核和问题处理连起来。
4. 人工对照协议已有，但没有本人执行的观测。本轮只准备入口及记录说明，不自动填写人工语义结论或耗时。
5. AI/RAG/BRAIN、真实数据、远端 CI 继续保持现状；不改基础视觉设计，不重写因子引擎，不扩大既有独立数值参考的声明范围。

## 契约与正确性边界

- ResearchCreate 增加可选 idempotency_key；旧调用保留行为。新前端先保存固定请求再提交，同键同正文确认原创建结果，不改绑到后续修订；异正文返回 409。请求收据与研究/初始修订同事务。
- 实验提交复用已有后端 key，不改变历史运行语义；前端耐久保存正文和 key，响应丢失/页面刷新后继续确认同一 run。保存成功与后续读取失败分别展示。
- 草稿先清理、再确认请求；无法持久保存则不发送。不确定结果不能换 key 静默重发；明确的新操作允许使用新 key。
- 实验对比只读取已保存的结果。条件、候选公式、数据版本、时间区间、执行语义、运行状态及覆盖差异分别展示；不把表达式变化本身当作不可比条件。未知/不一致条件或未验证产物不生成指标差值，缺失值不填零。
- 比较声明的是评估条件兼容，不代表语义正确、投资有效或统计显著。预算/工具次数/耗时按实际记录展示，不推断研究效率。
- 研究总结按明确选择的少量实验生成冻结快照；所有研究修订、证据与声明归因、所选实验的失败/尝试/审核，以及相关问题与回归记录均保留。明确选择范围和计数；超过上限显式拒绝，不静默截断成完整研究。
- 快照存入 schema 6 的 research_reports 表，具有请求去重、内容摘要和唯一标识；JSON/Markdown 从同一持久快照生成，下载检查摘要。后续新增审核不改变旧报告。
- 新报告自身完整性与原运行产物核验状态分别记录。保留原始代码/数据/配置标识和可定位的产物引用，不生成或重新计算金融指标，不导出本机绝对路径。
- schema 5→6 原子迁移；不伪造旧操作收据或历史报告。备份恢复应保留原收据及冻结报告。

## 执行顺序

评估与本清单 → 隔离旧预览 → 三 agent 并行、主线程集成 → 交叉审查与定向修复 → 冻结源码 → 新 release-v08-* 目录统一验收 → 本地 commit/tag → 备份并恢复至新工作区 → 核验历史与页面。

失败保留原输出目录，修复后使用新目录。最终状态、实际计数和限制写入交付目录，不改写旧基线和旧实验。本轮人工试用执行仍由本人完成。

## 集成与交叉审查记录

- 三组共享契约确认后并行实现；研究界面 agent 追加负责独立工作区内的研究创建/运行提交 E2E，主线程仍负责共享恢复 hook、API、生成文件和整体验收。
- 迟到 4xx 写回或成功响应清理前，核对持久请求身份；不清理新的请求及草稿。创建恢复携带原草稿标识，复制研究与空白入口之间切换也能清理正确副本。
- 数值可比性指纹涵盖历史 worker、工作流、输入配置及结果写出依赖；不只比较算术算子文件。缺少历史绑定视为未知。
- 冻结报告补齐问题事件显式引用的外部检查/案例/审核，标明外部上下文数量；未选外部 run 不冒称已验证。
- 报告目录有每页资源上限，基础界面提供小页读取，避免多份合法大报告导致目录无法浏览。
- 真实 HTTP 示例完成研究、实验、报告提交后丢响应、并发确认、带来源的非零差值、条件不符阻断和恢复后冻结导出检查。所有示例反馈标为 automation。
- 正式冻结后的统一验收计数、运行时迁移和交付状态只记入新 release-v08 目录；开发阶段通过不替代最终验收。
