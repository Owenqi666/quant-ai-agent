# v0.20 integration contract

Baseline 0.19.0/schema15. Root owns schema16/API/typed frontend/release/live workspace. Agents own only the files listed in the task plan and report actual signatures/models early. No live var edits, no AI provider/network or broad UI design. New immutable resources must use bounded canonical payloads, metadata digests, durable exact-request receipts, source verification and transactional final fences. Old resources and receipts remain byte compatible.

Integrity is relative to existing local ledger rows, receipts, source files and saved release/backup evidence. A missing row referenced by a surviving receipt/child is rejected. Consistently deleting an unreferenced row and its only receipt, or rewriting the whole database and all hashes, cannot be detected without an external trusted checkpoint. Hashes are not authorship authentication; this release does not claim resistance to a complete local-history rewrite.

## ClaimReviews

New SCHEMA exported from server module. Service target(claims_id,claim_id) creates typed projection with complete exact original lineage and target digest. preview/create carry that digest and explicit reviewer/source/time/five dimensions/reasons plus optional exact supersedes ID/digest. get/list/status/export verify original target each time. Human statements never overwrite automation draft or numeric verification. Scope for active chains: target digest + source + reviewer. All relevant ledger rows verified before filtering and active status/conflict projection. Client cannot supply metric values/provenance/approval. Automation-only demo writes isolated workspace.

## SemanticEvaluationSets

New SCHEMA and typed service. preview determines current complete human reference ledger for chosen cases; create includes accurate expected material digest and active IDs/digests to prevent hidden or stale reference selection. Frozen contents include original annotation snapshot/history links sufficient for audit plus exact case/material/source snapshots. Old set verification must remain valid after legitimate new annotations; verify old referenced immutable records, do not require them to remain current. Cross-reviewer conflict and any unknown outcomes remain explicit by dimension. Automation never provides human ground truth. Comparison binds exact set and submitted complete case dimensions; output rate is declaration agreement only, not model quality (always null without model integration). Export bounded bytes through typed service; CLI permits explicit local destination, HTTP accepts no paths. Offline verifier must detect source/snapshot/manifest tampering; snapshot identity alone is integrity, not trusted authorship.

## ResearchBindings

New SCHEMA and typed service accepting existing protocol ID/digest + author study ID/digest and explicit source/scan lineage validated by narrow core model. Root may adapt exact chosen request once published; no arbitrary path, URL or executable in HTTP. Frozen projection includes paper digest/evidence references, source metadata, declared scan/plan/aggregate, exact panels/source version and compatibility decisions. Existing public MAT audit/scan validators reused. Distinguish declared imported archive provenance from actual raw-source verification now; client booleans never make raw_source_reverified=true. Local verification receipt identifies actual fixed bytes and applicable scan verification scope and limitations. Generic readiness manifest has a 64MiB source bound and is not repurposed for these MAT archives. No eligibility declaration grants portfolio authority; method blockers retained even when counts pass. Every get and receipt replay revalidates protocol/study/associated evidence. Portable demo is clearly synthetic; real local scan/source proof separate and not redistributed.

## Integration and delivery

Each package's demo takes --out NEWDIR and emits result.json with passed, scope, human records zero and no provider call. Root composes demo_v020.py, adds additive schema and validates prior versions, exposes typed APIs and basic controls. Agents independently cross-review another package before release. New tests must cover real contract boundaries (not mirror implementation). Freeze code before full gate. Accepted package handles clone/original upgrade; every previous row/file/digest preserved offline, health/runtime/JS/CSS identities checked afterward without domain writes or human labels.
