# v0.13 月度 MOM / ID 数值与覆盖契约

此模块处理 `controlled_fixture` 日总收益，提供信号与覆盖诊断。它没有运行市场回测，没有证明真实市场日历、收益调整语义或论文收益结果。交易日历完整性是输入声明；程序检查声明内部的一致性，不能凭空发现被错误省略的真实交易日。

## 时间与缺失

- 目标月份 t 与信号形成日期分开：as_of 是 t 前一月的最后一天。这里是日期规则，不是成交时间或实际发布时刻认证。
- 项目默认使用 t−12 至 t−2 的十一完整自然月。ID 与 MOM 同窗属于项目约定；论文模式的 ID 日频窗口和缺失规则保持未决，不能计算。
- 日期窗口由配置展开。应有观察数来自声明的 sessions，不从收益行推断。缺行与 null 分别统计；休市日不计入应有数或缺失连段。
- 只要窗口开始早于资产 history_start，就拒绝该字段的计算。available 不放宽历史要求，不把窗口缩成最近 N 个观察值。
- complete 要求完整覆盖；available 按配置检查覆盖和连续缺失上限，至少需要一个有效收益。available 仅复合观察到的有效收益，不代表存在缺失时的完整窗口收益。任何规则都不填补收益，零收益计入 ID 分母。
- MOM 和 ID 可选择不同窗口；分别检查资格和保存原因。某字段不合格不会清除另一个合格字段，但资产整体不能被标为 ready。

## 数值规则

输入收益为有限 binary64 数值，单位是小数；−100% 合法，低于 −100% 非法。配置中的整数、数字不接受 bool。JSON 不允许 NaN 或 Infinity。

常规复合使用 `expm1(fsum(log1p(r)))`，避免逐项计算 `1+r` 时把很小的正收益抹成零。若任意有效收益等于 −1，累计收益为 −1。溢出返回 null 并记录 `nonfinite_compound`。

ID 依赖 PRET 符号，不能把复合舍入误差变成方向。手算例子 `[7, -0.5, -0.5, -0.5]` 的 gross product 为 `8 × 1/2 × 1/2 × 1/2 = 1`，PRET 应为零；普通 log reduction 在本机得到约 −1.11e−16。当前实现当累计 log 靠近累计舍入尺度时改做精确二进制有理积，绝不按 epsilon 把答案置零。相邻浮点输入的真实正负差异仍保留。

精确路径先约去二的幂，再计算整数积，每个字段的整数位数预算为 100,000 bit。超限返回 null 和 `compound_precision_budget_exceeded`；精确非零差值小到不能表示为 binary64 时返回 null 和 `compound_precision_underflow`。这些失败保留覆盖计数，不伪装成缺失或零信号。

精度契约针对规范化输入的浮点数，不把它们假装成无限精度原始行情。测试使用独立 Fraction 手算预期和精确可表示反例，不使用生产计算函数生成答案。

## 输入与身份边界

最多 128 个资产、6,000 个 session、100,000 条收益记录、300,000 个 calendar×asset 单元、7,320 个覆盖自然日及 16 MiB 规范 JSON。sessions 严格递增且唯一，收益记录可乱序但资产/日期键唯一。非 session 收益、未知资产、历史开始前的收益及范围不足均拒绝。

`config_digest(config)` 是保存和预览共同使用的入口：先规范化配置，再用排序键、紧凑分隔符、UTF-8、末尾换行、拒绝非有限值的 JSON 计算 SHA-256。`input_digest` 绑定传入 bundle 的 JSON 内容，包含未来行和行顺序；改未来数据会改变输入身份，但不会改变已形成的信号。输入函数不修改调用方的对象。

演示日历是虚构的周一至周五集合，不是任何交易所日历。COMPLETE 每月 +10%、−5%、其余零，单月复合 4.5%；ASYMMETRIC 另加一个 +1% 日，十一月默认窗口的 ID 为 `−11 / expected_sessions`。缺行、null、历史不足资产用于展示拒绝原因。
