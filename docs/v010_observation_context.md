# v0.10 观测表单的只读上下文

人工只需要选择研究、实验和自己的审核。固定协议摘要、内部 ID、确切结果与报告引用由后台提供；这些便利不创建人工观测，也不降低 v0.9 的预检和不可变保存要求。

## 接口

`GET /api/researches/{research_id}/workflow-observation-context`

可选参数为 `revision_id`、`run_id`、`attempt_id`。不传运行时只返回协议、兼容性、服务环境和运行列表。传运行但不传尝试时，返回尝试列表，不暗选最新尝试。明确传运行而未传修订时，使用该运行所属的修订；明确提供的修订必须与运行一致。尝试不能脱离运行查询。

实现为 `ObservationContextService.get_context()`，闭合响应模型为 `ObservationContext`。数据库连接启用只读事务；不写入观测、审核、请求回执或工作区设置。调用不读取任意客户端文件路径。

顶层字段：

| 字段 | 作用 |
|---|---|
| `research_id` / `revision_id` | 当前明确作用域 |
| `protocol` | 协议 ID/摘要、冻结任务摘要、候选及执行模式 |
| `compatibility` | 复用旧观测绑定规则检查论文、数据和完整科学条件；不兼容时提供中文原因 |
| `runtime` | 服务版本、代码摘要、服务端架构/系统/Python/依赖；提交无可靠映射时为 null |
| `runs` / `runs_total` / `runs_truncated` | 最近 20 条运行摘要、真实数量与截断标记 |
| `selected` | 显式选择后的运行/尝试上下文；未选运行时为 null |
| `limitations` | 声明边界，不作人工完成或真实性认证 |

`selected` 保留尝试的真实状态、是否通过核验、中文错误、完整 `bound_outputs`、最多 20 条尝试和结构化审核及其数量/截断标记。更早的运行/尝试可通过已知确切 ID 读取，不要求其必须出现在首页。当前审核选择器不提供翻页，只暴露前 20 条的明确上限。

## 精确绑定

1. 先复用 `WorkflowObservations._binding()` 核对固定协议的论文、数据、假设、表达式、预算和区间。默认三候选示例与本协议不兼容，不会被自动改写为单候选任务。
2. 尝试路径由工作区/运行 ID/尝试 ID 构造，不使用请求文件路径，也不使用数据库中的 `output_dir` 别名。历史尝试使用自身 state 和清单，后续重试不会替换其结果。
3. 预先检查快照和导出目录、文件数、字节数与所有快照引用，拒绝目录逃逸、符号链接、硬链接和特殊文件，再调用原绑定/完整性核验。运行中或无核验产物的尝试仍可显示，不能声明已核验完成。
4. 报告引用使用 `/api/runs/{run_id}/artifacts/{artifact_id}`，绑定确切尝试的已验证报告，不引用会随重试变化的“最新报告”地址。
5. 审核必须与所选运行/修订/尝试/候选及结果摘要一致；结构化 assessment 的预期尝试和摘要也需吻合。来源、参与者、五维判断和已有时间原样提供。损坏或不匹配的审核不列为可选。

返回的 `bound_outputs.review_ids` 始终为空。界面须让用户明确选择自己的 human 审核，再引用该审核 ID 和维度；不会把自动化或其他人的判断默认转成人工记录。审核时间不自动追加，不根据实验墙钟时间填六阶段。正式保存仍重新调用原有校验器。

## 环境与代码来源

`runtime.environment` 使用现有 `ObservationEnvironment` 结构，但描述当前服务：`machine` 为架构，`os` 为平台字符串，`python` 为解释器版本，`dependencies` 为固定依赖版本的稳定 JSON。它不认证用户设备，也不保证外部 CLI 和服务端环境一致；用户应一次性确认对照条件。

代码摘要由有界服务源文件清单计算。提交只接受 `portable_source_commit(REPO)` 对本机构建清单全部文件一致性核对后的映射；旧包缺少映射、源码改动或无可靠来源时 `code_commit=null`、`code_commit_verified=false`。不执行向父目录查找 Git 的命令。此处的 verified 表示本地清单映射已核对，不是签名认证、远端 Git 证明或历史尝试源代码认证。

## 边界与错误

- 列表固定上限 20；原始审核总数可包含不匹配、因而未显示的记录。不会为获得完整列表而扫描全部审核内容。
- 快照最多 3,000 个普通文件、256 MiB，总目录条目不超过 9,000；单文件 64 MiB，读取的 JSON 16 MiB，单条审核 1 MiB。达到上限返回 413。
- 跨研究/修订/运行/尝试或模式不符返回 422；不存在的对象返回 404；文件损坏/丢失等上下文异常返回中文 409。所选尝试的核验失败显示 `verified=false` 和原因，隐藏结果及审核快捷引用。
- 字段方便填写不代表观测已经发生；参与者、来源、顺序、实际计时、结束状态、外部 CLI 引用与真实研究判断仍需本人确认。
- 对照分组、观测协议和旧数据库 schema 不变。上下文预填后若条件变化，按旧协议保留不可比较状态，不为配对而改写事实。

## 定向验证

```sh
.venv/bin/python -m unittest tests.test_observation_context -q
```

所有研究/审核都在临时工作区生成，并明确作为自动化夹具，不增加实际人工观测。覆盖只读无副作用、无 Git 父目录推断、显式历史修订、列表上限、运行模式/作用域、未完成与历史尝试、精确报告引用、审核来源/指纹、快照篡改与目录外引用等边界。
