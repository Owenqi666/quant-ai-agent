# v0.9 流程观测界面与恢复约定

## 使用

选择研究后打开「流程观测」。页面维持现有基础表单和表格样式，不改动研究工作台视觉设计。

1. 下载服务端生成的空白观测 JSON。协议 ID、协议摘要和固定任务摘要来自后端；参与者、来源、时间与结果保持留白。空白模板的 `record_status` 为 `pending_human_observation`，不能提交。
2. 按真实使用情况填写文件，上传或粘贴到 JSON 编辑器。文件须非空、扩展名为 `.json`、不超过 256 KiB。明确选择「本人实际观测」或「自动化验收样例」；选择必须与 JSON 的 `source` 一致，页面不会自动替换来源。
3. 点击「预检观测记录」。浏览器拒绝格式错误、重复键（包括 Unicode 转义后的同名键）、过深嵌套、非有限数字、来源不一致和待填写模板；其他严格字段、区间、协议和结果绑定由服务器核对。字段不会被静默移除。
4. 检查输入摘要、每阶段耗时和绑定限制，再明确确认不可变保存。已观测主动工作合计与六阶段完整主动耗时分别显示，缺失不变为零，中断不补结束时间。预检不写入观测，也不产生人工审核结论。
5. 导入成功后可读取详情、导出完整 JSON，或按 1 / 5 / 20 项分页查询历史。内容完整性校验不能证明声明者身份、真实工时或研究结论。
6. 点击「计算观测汇总」。显示服务器返回的人工分母、完成情况、自动化和练习记录，以及可比性原因。界面不自行计算研究耗时差值。下载的汇总保留当前服务响应、生成时间与原始记录；新增记录后需重新计算。

## 输入和引用

仅支持后端注册的固定协议，模板并不是通用的任意论文效率评测配置。工作台路径需要真实修订、运行、尝试和审核身份；外部 CLI 路径只保存声明引用，服务不读取任意本地路径。当前研究与修订仅在页面展示，不会替换 JSON 中的原始 ID。

`human` 是使用者的显式声明，不是身份认证。自动化 E2E 样本声明 `automation`，所有测试时间、参与者和环境均是软件测试夹具，不能写入真实人工效率成果。

## 浏览器持久化和恢复

- 草稿按工作区及研究隔离，保存在当前浏览器。它不属于服务器备份，也不会跨设备同步。上传新文件后清除旧来源声明，要求重新确认。
- 保存前使用现有 `useRecoverableMutation` 将完整原请求和幂等键耐久保存到本机，并读回核对。存储失败时不会发送请求。
- 网络失败或响应不符合契约时，原请求保持待确认，编辑与新提交被锁定。重载后使用「安全重试观测导入」，仍发送原正文和原键。
- 明确的非冲突 4xx 拒绝可解除后修改；409 和未知结果保留原请求供诊断，不自动制造新键。
- 服务保存成功与列表刷新成功分开显示。列表暂时失败时，已确认的固定详情和导出入口保留，不误报保存失败。
- 原请求确认后只清除匹配其提交快照的草稿；其他窗口后续写入的草稿不会被迟到响应删除。
- 切换工作区或研究会重新挂载内部组件。文件、预检、列表、详情与汇总分别使用请求代次，旧响应不能写入新选择；A → B → A 也不会复活第一次 A 的响应。

## 集成与验证

入口组件：`frontend/src/components/WorkflowObservations.tsx`。

```tsx
<WorkflowObservations workspaceId={workspaceId} researchId={research.id} revisionId={revision?.id} />
```

组件消费生成的 OpenAPI 类型，并使用现有严格响应检查。请求路径为 `/api/researches/{research_id}/workflow-observations` 下的预检、保存、分页、详情、汇总及导出；空白模板来自 `/api/workflow-observation-template`。

专属测试：

- `frontend/src/workflowObservations.test.ts`：JSON 歧义、来源、大小、作用域、草稿耐久保存、迟到确认、请求代次与缺失时间。
- `frontend/e2e/workflow-observations.spec.ts`：空模板拒绝与自动化来源隔离；丢失已提交响应后的原键恢复；列表失败保留成功；研究切换抑制旧预检；存储不可用时禁止发送。

浏览器测试沿用 Playwright 的临时工作区与测试服务，不连接 8765。测试只建立专属研究和自动化外部声明记录，不创建运行、审核或回归用例，避免污染原有流程测试的全库计数。执行命令与实际结果由最终发布验收记录提供，不以文档声明替代运行日志。
