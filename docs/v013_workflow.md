# 时间窗口和缺失规则：v0.13 操作说明

这一轮新增独立的「研究规则」入口。它验证月度 MOM / ID 定义、取样日期和缺失处理；旧 Alpha101 日度实验仍使用原有任务契约。新规则尚未接入真实行情、月度组合收益或既有日度回测。

## 工作台操作

1. 打开工作台，点击「研究规则」，无需先选择研究或导入数据。
2. 查看两个预设：「论文原文」保留未确认的 ID 日频构造；「项目约定」提供可执行的 11 自然月、跳过最近 1 月、完整覆盖规则。论文预设不能直接改成猜测参数，修改需要显式使用项目模式。
3. 选择目标月后预览。例如目标月 `2026-07`、窗口 11、跳过 1，展开为 `2025-07-01` 至 `2026-05-31`，形成时点为 `2026-06-30`。目标月指之后要研究的持有月，当前预览不计算该月的收益。
4. 检查演示资产的 MOM、PRET、ID、应有交易日、有效观测、缺行、空值与连续缺失，以及不可计算原因。输入是虚构工作日日历和受控收益夹具，不是交易所行情。
5. 保存规则版本。再次修改窗口或高级缺失参数，保存为派生版本；记录会保留来源、未决项、父版本和参数差异。相同正文重试返回原记录。规则版本不包含预览月份；预览 JSON 单独下载。

## 两个问题的明确答案

**窗口可以由使用者选择，但来源与改动必须分开。** 论文可确认 MOM 的 `t-12..t-2`；作者代码使用 `DGW[t-1]`，并不能证明 DGW 内部每天如何取样。因此论文模式的 ID 窗口保持空值且禁止输出信号。项目默认 MOM 和 ID 都用 11 自然月、跳过 1 月，这是本项目采用的可验证约定。窗口调整生成新版本，不能称为论文原式复现。自然月按月份边界展开，不换算成固定 21 个交易日。

**缺失处理依据声明的完整日历，而不是收益文件中剩下的日期。** 日历声明区间内所有预期开市日，非开市日不进入分母；缺行与显式 null 分开记录。零收益是有效观察，进入 ID 的有效日分母。缺失不前填、不补零；历史起点晚于窗口起点时拒绝该资产，不把新上市资产自动改成短窗口。

默认 `complete` 要求全部预期交易日有效。高级 `available` 必须明确最小覆盖率和最大连续缺失交易日：仅用有效观测复合收益，因此缺失存在时不能称为完整窗口收益。ID 分母也是有效观测数，缺失日不计入。周末和休市日不打断按交易日计的缺失连段。日历真实性及复权规则是输入声明，当前工具并未对接外部源来认证它们。

## 可复算的完整快照

```bash
.venv/bin/python scripts/preview_research_protocol.py \
  --preset project --target-month 2026-07 --out artifacts/my-protocol-preview
.venv/bin/python scripts/preview_research_protocol.py --verify artifacts/my-protocol-preview
.venv/bin/python scripts/demo_v013.py --out artifacts/my-protocol-comparison
```

每次使用新输出目录。CLI 保存 `config.json`、`input.json`、`report.json`、`manifest.json`，包含来源、未决项、文件摘要和核心代码摘要。`--verify` 检查摘要并重新计算输出；它是本地一致性核验，不是第三方签名认证。可用 `--config` 提供完整规则、`--bundle` 提供契约内的 controlled_fixture 日总收益。价格、百分数单位、真实行情身份和不完整日历不能静默转换。

`demo_v013.py` 对照论文未决、项目完整、项目允许部分观测、六个月变体，保存规则版本并验证备份恢复。数字是夹具的算术结果，只用于软件验收，不是投资收益或人工评审成绩。缺失和失败资产保留在输出中。

## 工程边界与后续接入

schema 9 仅新增 `research_protocols`，原实验与审核记录不重写。备份支持 schema 1–9；升级后不要用旧软件直接打开 schema 9，回退须使用升级前备份。新 API 的配置和结果进入既有 OpenAPI / TypeScript 契约检查。

下一步需要为一个明确数据源实现日总收益、证券存续和交易日历适配，再冻结月度样本/分组/权重/收益对齐契约及独立参考。当前界面保存规则不会自动改变旧 Alpha101 任务，也不会解除真实市场数据或最终测试的限制。
