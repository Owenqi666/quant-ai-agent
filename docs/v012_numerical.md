# v0.12 相关算子的数值契约

本轮修复的是合成 fixture 的软件计算正确性，不增加真实数据、交易成本或最终 test 执行能力。评估器的排名、gross=1 权重、有效样本分母和 test 隔离规则保持原样。

## 已复现的问题

- 旧版 `ts_corr(close, close, 3)` 在同一天给出 `1.0` 和 `0.9999999999999999`。在随仓库提供的 validation 配置中，126/128 个可评估日期因此产生了本不应存在的截面排名与组合。
- 合法表达式 `ts_corr(close/1e-200, close/1e-200, 3)` 的平方范数溢出后得到零；乘以 `1e-200` 时范数下溢，得到缺失。旧诊断没有将算子内部的溢出识别为最终 Inf。

原始证据保存在 `artifacts/v012-numerical-before-01/`：旧算子和参考源码、输入摘要、原始输出以及 `reproduce.py`。该目录是新建的本轮证据，未改写以往发布产物。重放脚本显式载入其冻结的旧 expression 源码，使用仓库中的合成数据与评估工具；它是数值问题重现工具，不是完整历史服务部署包。

## 新契约

算子版本为 `local-panel-v3-scaled-corr-exact-boundaries`。

1. 每个窗口使用实际传入、已经表示为 binary64 的观测值。完整窗口不足、有缺失或任一序列严格恒定时，相关系数缺失。窗口为 1 也缺失。
2. 非恒定的完全相同输入返回严格 `+1`，完全相反的输入返回严格 `-1`。
3. 常规路径先减去首个观测，再按最大绝对差归一化，最后去均值并计算 Pearson；在平方之前缩放，避免大量级溢出和小量级下溢。计算不依赖平台上 `longdouble` 是否宽于 float64。
4. 首次相减溢出，或初步系数在零或端点附近时，使用精确路径。选择界限为 `32 * float64 epsilon`，**它只选择计算算法，不把结果吸附为零或端点**。
5. 精确路径通过 `float.as_integer_ratio()` 将每一轴表示为共享二进制分母下的整数。Python 整数计算方差与协方差矩，不发生浮点平方溢出或抵消。零方差、零协方差和严格仿射关系由整数等式判定；其余结果以 80 位 Decimal 开方、相除，再转换为 binary64。Decimal 使用独立 context 和 ROUND_HALF_EVEN，不继承调用方的全局精度、舍入或指数范围。
6. 不宣称所有无理数结果都保证数学上的正确舍入；普通浮点路径仍存在浮点误差。精确路径保证的是输入表示和整数矩的准确性。输入进入算子之前已经被浮点运算舍掉的信息无法恢复。

没有增加因子全局 epsilon、四舍五入、排名容差或统一平局规则。近相关的可表示差异仍能产生不同排名；数值为 `1e-200` 量级的合法因子仍能产生与原因子一致的权重。

## 独立参考与历史边界

参考版本为 `stdlib-seven-formulas-v4-exact-corr`，审核的算子版本明确固定为新的 v3 字符串，不从生产常量自动推断兼容性。

独立 Alpha006 参考通过 `Fraction.from_float()` 减去精确有理数均值，再累加中心化有理数乘积；最后使用独立 context 的 100 位 Decimal。它不导入生产相关系数 helper，计算结构也不使用生产的整数原始矩。其他六个登记公式保持既有独立实现；这次没有扩大公式支持范围。

历史 v2 文件继续通过原有记录读取逻辑识别。新参考对 v2 数值产物返回 `not_comparable / oracle_unsupported_semantics`，不会重新计算或改写历史实验，也不会以新契约为旧指标背书。科学契约比较会保留 `operator_semantics` 差异。新产物中的 expression/factor 诊断版本还必须与冻结源码声明一致，版本不符返回失败。

## 验收

专属测试：`tests/test_numerical_v012.py`。

- 实际 fixture → 表达式 → 排名 → 评估：自相关及缩放自相关为不可评估常量，不产生组合；对照的合法微小信号仍保留权重。
- 直接验证正、负仿射相关，正交、近零非零相关、近完美但不相等的相关；覆盖大偏置、极大／极小／次正规数，以及相减可能溢出的正负极值。
- 缺失传播、完整窗口、常量与单元素窗口保持既有定义；前缀及未来扰动不改变过去。
- 独立参考不调用生产 helper；当前版本可复核，历史 v2 可读取但不可获 v3 数值通过，诊断版本伪装会失败。

窗口 252 的参考 helper 测量不意味着独立参考支持了新公式。登记的相关公式仍只有窗口 10 的 Alpha006，并保留总行情 100,000 cells 和相关计算 1,000,000 observation operations 的上限；参考 helper 自身也拒绝超过 252 个观测的窗口。真实完整任务仍受外层进程超时和预算控制。

精确参考有明显的计算成本，不能宣传为性能提升。这些时间仅包含算子或参考的计算，排除了导入、进程启动、文件核验、序列化及其他任务阶段；不能据此承诺完整任务吞吐或所有输入都能在默认预算内完成。对近边界相关特别密集的工作负载，生产路径也会更频繁地进入精确分支，应保留预算停止而不是降级成未经验证的数字。
