# Alpha101：第一轮人工审核

本阶段复用已有冻结实验，为它准备三条自动化草稿：论文公式、工具指标、研究限制。草稿没有人工审核结论；材料标签也没有预先填写。当前计算使用合成日度数据和 validation 区间，不能据此判断实际投资收益。

## 先完成一次准确文字审核

1. 打开 <http://127.0.0.1:8765/>，左侧选择 **研究任务**。在“已保存任务”点击 **Alpha101：用户选择材料的可复现开发案例**。不要新建任务或重新运行实验。
2. 在该任务下展开 **带实际数值引用的结论草稿**，点击已有的 **查看结论草稿**。页面展示三条待审文字及服务端计算的实际值。在 **选择具体结论** 中先选择 `alpha101-paper-formula`。
3. 对照论文 PDF 第 15 页的 Alpha #101、页面中的精确证据和公式。展开 **填写本版本的五维判断**，声明来源选择 **本人实际审核后的判断**，填自己的标识，点击 **记录结论确认时间**。五个维度分别选择判断并写明理由；没核实的选“尚未评定”，确实不适用的选“不适用”并说明原因。点击 **预检本版本结论审核**，检查预览后点击 **保存本版本结论审核**。

这里审核的是当前选中的准确文字版本。不要根据数值引用已核验就直接把经济解释判为通过，也不要把旧实验中的简短审核当成这份文字的新判断。完成一条即可形成第一份可追溯人工记录，其余两条可以逐一审核。

## 判断时看什么

| 维度 | 需要实际核对的内容 |
|---|---|
| 引用与页码准确 | 来源 PDF、页码、Alpha 编号及所引公式是否对应 |
| 假设忠于所引原文 | 是否准确限定为论文列出的公式；项目没有据此宣称原文证明了收益或机制 |
| 经济解释归因恰当 | 项目解释或推测是否被当成论文事实；没有机制主张时可注明不适用 |
| 字段含义与替代说明 | open/high/low/close 是否对应声明的输入；真实市场字段的适用性仍未验证 |
| 实现与声明公式一致 | 冻结表达式与原文公式是否一致；若要判断算子实际语义，须另查实现及测试，不能只看表达式 |

工具指标草稿中的数字来自保存结果的精确 JSON pointer。`mean_gross_return` 是本地配置下的毛收益计算，未覆盖真实交易费用与市场可执行性。数字对应正确和研究结论正确是两项不同的审核。

## 材料标签与后续基线

如果还要建立人工参考，在左侧 **语义评测** 选择 `alpha101_formula`，打开来源 PDF，填写 **自己的材料标注**。这份判断只评估固定材料，不会自动批准前面的草稿。只有本人填写的材料记录存在之后，再冻结版本化参考集并开展比较。

当前准备工具不产生人工耗时或流程优势数字。比较 CLI/editor 与工作台时，需要本人分别执行固定协议、记录真实主动工作时间并提交流程观测；软件演示或自动化测试不能替代这个对照。

## 可复核的导出包

交付目录：`artifacts/v020-human-preparation-live-01/bundle/`。包括原始 [paper.pdf](../artifacts/v020-human-preparation-live-01/bundle/paper.pdf)、完整 `packet.json`、原提交请求、运行身份、文件摘要清单和 `report.md`。[交付记录](v020_human_preparation_delivery.md) 记录实际生成的草稿批次、准确目标和验收结果。

离线核验不访问工作台：

```bash
.venv/bin/python scripts/prepare_human_review.py verify \
  --out artifacts/v020-human-preparation-live-01/bundle
```

追加 `--live` 会只读核对当前工作台的准确版本。离线摘要检查只能发现输入之间不一致或文件损坏，不构成对原始出处、人工身份或金融有效性的认证。

遇到创建请求丢失响应时，用工具打印出的 `resume --out <原目录>` 恢复原键。不要改原目录的请求内容，不要换工作区重试。
