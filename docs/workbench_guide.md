# 工作台使用、验证与恢复

## 一次完整的人工研究流程

1. 按 README 安装并启动，进入 `http://127.0.0.1:8765`。状态区应显示 worker 在线。
2. 点击「导入示例研究」。材料是用户已确认使用过的《101 Formulaic Alphas》，数据为版本化合成 OHLCV。现有自动生成的实验和审核仍只是工程演示，不成为个人实际审核或市场成果。
3. 在研究工作台核对页码、原文引文、假设、候选公式和数据字段。PDF 下载链接可检查原页。AI 区域明确关闭。
4. 选择执行策略并提交实验。「固定执行」不会修复别名；「规范化后固定执行」预处理已声明别名；「有界修复」根据确定性工具错误修复。三者均不调用模型。
5. 在实验记录查看状态、事件、每个候选的原因、指标和产物。Alpha #5 缺少 VWAP 时受阻是正确行为。指标来自验证区间；最终测试区间锁定。
6. 对具体候选填写审核结论、错误分类和说明。审核绑定本次版本、尝试及结果哈希，不改动原结果。
7. 明确填写预期状态并批准为开发回归样本。批准行为来自用户操作，系统不会把自己的输出自动变成标准答案。
8. 返回研究工作台，编辑任务并保存新版本，填写修改理由。修改原始假设时应同步调整归因、字段、假设和 changes；修改后的公式不得继续冒称原文结论。旧版本保留。
9. 提交新实验，在审核与回归页面选择样本执行检查。后台比较冻结的假设、证据、公式、数据和评估配置，区别显示通过、失败和不可比较。候选有评估结果时，还要通过引用核对及受支持公式的独立数值计算；未产生数值的负例只检查明确批准的预期状态。展开检查记录可查看差异路径、容差和参考实现版本。引用匹配不代表经济解释已经正确。

未知论文可以上传文本 PDF 并手工填写结构化任务。扫描 PDF/OCR 和任意论文自动理解未实现。v0.5 创建与修订共用基础表单，逐项维护原文、假设、归因、候选表达式、时间切分与预算，并展示修订差异；高级 JSON 入口保留。服务端拒绝文件路径、额外字段、非法 JSON 和不合法的时间切分。

草稿保存在当前浏览器本地，恢复前需要明确选择；与工作区、研究和基修订隔离。草稿不是服务器修订，也不随服务器备份迁移；只有保存成功才成为正式研究记录。清理浏览器数据会丢失未保存草稿。原文匹配只确认文字存在，不会自动批准经济解释。完整 Alpha101 人工步骤与待审表见 [案例协议](../evaluation_suites/v05/README.md)。

## 自动演示同一条链路

在工作台运行期间，从另一个终端执行：

```bash
.venv/bin/python scripts/demo_workbench.py --out runs/http-demo-01.json
```

脚本通过真实 HTTP API 创建新研究，使用固定流程运行原始别名，记录明确标为自动验收样例的审核，批准预期 `evaluated` 的回归用例，先得到失败检查，再通过新版本把 `correlation` 规范化为 `ts_corr`，重跑后得到通过检查。它检查旧结果没有被覆盖。此演示不是用户本人做过的人工审核；不测量研究效率或投资收益。

再次运行请选择新的 `--out` 文件。启动在其他端口时传 `--url http://127.0.0.1:8766`。

## 开发与测试

生产构建由 API 同源提供，通常只需 README 的一条启动命令。开发时可分别启动：

```bash
.venv/bin/python -m uvicorn paper_alpha.server.api:create_app --factory --host 127.0.0.1 --port 8765
.venv/bin/python -m paper_alpha.server.runner
npm --prefix frontend run dev
```

三个命令分别占用一个终端。Vite 页面在 `127.0.0.1:5173`，代理保留 Host；API 拒绝跨来源写操作。不要通过修改 CORS 或绑定公网来绕过本地部署边界。

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/export_api_contract.py --check
npm --prefix frontend run build
npm --prefix frontend test
cd frontend
npx playwright install chromium
npm run test:e2e
```

本机已使用安装的 Google Chrome 完成验收，也可以执行 `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`，无需再下载 Chromium。CI 默认使用 Playwright 管理的 Chromium。

浏览器测试启动隔离服务及工作空间，使用真实后台 worker；不会清空你的日常研究数据。CI 配置位于 `.github/workflows/ci.yml`，随仓库交付；未推送到远端前不声称远端 CI 已通过。

## 状态与恢复

- 重复网络提交使用同一幂等键时返回同一任务；同键不同请求返回 409。
- 编辑冲突返回 409。刷新最新版本、合并自己的修改，再保存；不能静默覆盖他人或另一标签页的修改。
- 取消队列任务立即生效；运行中的取消会终止整个计算进程组。晚到的成功结果不能覆盖取消。
- 停止或丢失 worker 后，旧尝试保留为 interrupted。重启 worker 后在页面显式重试，最多三次尝试，每次使用独立目录和有界预算。
- 重试不是修改实验。调整输入或预算必须创建新修订/新实验。引擎 CLI 的 `--resume` 仍仅支持完全一致的输入、代码和环境。
- worker 锁在执行子进程中继承；若强杀后旧计算仍运行，新的 worker 会拒绝接管。等待该有界计算退出后再启动，不要删除锁文件强行并发执行。
- 完成结果的哈希或来源归属校验失败时，不允许继续审核或作为回归依据。保留目录定位问题，以新实验重新执行。

## 文件、备份和容量

`var/workbench/workbench.sqlite3` 保存版本、队列、审核和检查；同目录的 papers/datasets/runs 保存不可变素材和尝试产物。原有 `runs/`、`artifacts/` CLI 记录不会迁移或覆盖。

页面下载是去除服务器内部路径的导出视图，拥有各自哈希；它不是可直接交给 CLI `verify` 的完整重放包。完整原始输入、源码、工具记录和输出保存在 `var/workbench/runs/<run-id>/attempts/<attempt-id>/output/`，可通过 `paper_alpha verify` 核查。

备份前使用 Ctrl+C 停止整个工作台，再执行专用备份命令；恢复必须使用一个不存在的新目录。命令会校验文件清单、生成一致的 SQLite 快照并重定位数据库里的工作空间路径，原始实验文件保持不变。不要把手工复制的目录直接当作可移植备份。具体命令与失败处理见 [备份恢复说明](backup_restore.md)。用 [只读诊断](diagnostics.md) 检查容量及任务状态；当前没有自动清理历史记录，勿将 SQLite 放在网络共享盘上供多机 worker 使用。

## 升级与统一验收

v0.4/v0.5 启动时在独占迁移锁下按 schema 1→2→3 顺序升级；v0.5 未新增 schema 迁移。失败会回滚，未知版本拒绝启动。旧审核、实验和检查原样保留；旧状态回归案例没有科学条件快照，会显示需要重新批准。选择原审核并填写批准理由，可以创建新用例；不会修改旧批准。数据接入和问题回流见 [v0.4 操作说明](v04_workflow.md)。

```bash
.venv/bin/python scripts/verify_release.py --out artifacts/release-check-01 --browser-channel chrome
```

命令统一运行响应契约检查、Python 测试、前端构建和单元测试、真实浏览器流程、固定基线和两组任务集、数据回流与恢复、只读诊断，以及独立源码包安装与浏览器验证。输出 `acceptance.json`、每步日志及源码 SHA256 清单；任何检查失败、源码中途变化或输出目录已存在都会拒绝完成验收。CI 使用同一脚本，默认 Chromium。本项目当前用源码清单固定可复查的交付版本；远端 Git/CI 尚未配置或运行的状态不能写成已通过。

独立数值参考限定为 Alpha006、Alpha101、Alpha012 及明确去掉一次幂的 Alpha033 本地修改式，检查验证期及所需历史因子、t+1/t+2 开盘标签、逐日权重/贡献与汇总指标。其他可执行公式会明确显示参考范围不支持，不会仅因状态为 evaluated 就给出完整回归通过。自动参考无法判断假设是否有真实投资价值。

## AI 扩展边界

`paper_alpha/server/providers.py` 仅定义提案接口和明确失败的禁用实现；`/api/capabilities` 返回 `ai_enabled: false`。未来提案器只能给出待审任务草稿，仍需通过同一数据契约、来源检查和版本保存；没有权限写计算指标、批准审核或放开最终测试区间。

## v0.6：分项审核与输入定位

在“审核与回归”选择已核验实验和候选，可勾选“添加分项研究审核”。填写审核人标识，并分别判断引用、假设、经济解释归因、字段语义和实现一致性；每项都需要理由，未评定或不适用不能成为完整通过。普通审核的“接受”不自动产生这些标签。历史记录中的“查看审核目标与分项记录”保留完整 revision、attempt 和候选摘要；服务器发现结果已变化时拒绝保存。

需要记录本次审核的主动工作时，显式点击开始，在等待或离开前暂停，暂停后才能保存。没有区间就显示未记录，不能回填为零耗时。v0.7 起，切换候选或离开后可显式恢复该冻结结果的本机草稿；只有已结束区间恢复，未结束计时标为中断。保存成功后清理已提交副本；列表刷新失败仍明确显示审核已保存。来源和审核人只是声明，本地工作台不提供身份认证。

审核汇总对同一输出去重；主动区间按声明审核人合并重叠，不同人累计为人时。JSON 导出保留分项判断和区间，CSV 继续用于覆盖比例。该记录只覆盖主动记录的审核活动，不代表完整研究时间或相对人工流程的节省时间。

数据验证失败时，查看错误规则、记录行、字段、日期/资产和有限原值样本。CSV 行号指逻辑记录（表头第1行），quoted字段内换行不新增记录号；缺失网格没有对应输入行。报告只呈现首个失败规则的最多5个样本，不宣称已枚举所有错误。修改自己的原始副本后重新上传成为新收据，系统不静默修复原文件。

## v0.7：提交中断与草稿恢复

审核、批准用例提交前会保存固定请求。出现“结果待确认”时，用原请求安全重试；刷新后选回原研究和实验即可找到待确认请求，不需要重新填写。相同键只确认第一次操作；明确的新操作才使用新键。已经保存后的目录刷新失败不会成为重复提交的理由。

普通审核和分项审核都发送当前结果前置条件。新前置条件过期时返回 412，表示此次请求没有提交，可以解除后核对新结果。请求键冲突或收据异常为 409，需要保留原记录并诊断，不可随意换键重发。旧接口省略请求键的调用仍维持历史语义。

本机草稿和待确认请求不随服务器备份迁移，清理浏览器存储会失去客户端恢复线索。草稿需要明确选择恢复/丢弃；损坏或不可用的存储有可见提示。若固定请求不能先保存并回读确认，审核/批准不会发送，其他浏览和计算能力保持独立。只有服务器返回有效成功响应才确认保存；清理原草稿后再移除待确认请求，清理失败时保留原请求供确认。

服务回放只确认原操作曾成功保存，当前产物是否完好仍以实验完整性和回归检查为准。人工流程对照见 [v0.7 人工协议](v07_human_evaluation.md)，模板为空，尚无人工观测结果。

## v0.8：研究提交与总结

研究创建及运行提交现在使用耐久请求确认。刷新后从新建研究或对应研究的提交面板安全重试；保存成功与目录刷新失败分别提示。“研究对比与总结”提供保存的条件与指标来源对比，并按明确选定实验生成固定 JSON/Markdown 报告。操作和真实 HTTP 复现步骤见 [v0.8 工作流](v08_workflow.md)。
