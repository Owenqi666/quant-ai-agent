# 本机诊断与容量

```bash
.venv/bin/python -m paper_alpha.server.diagnostics --home var/workbench
.venv/bin/python -m paper_alpha.server.diagnostics --home var/workbench --out diagnostics-01.json
```

输出文件必须是工作区之外的一个新文件；不覆盖旧诊断。命令不初始化、不迁移、不修复数据库，不恢复/删除任务，也不更改原论文、实验、审核和结果。退出码 0 表示本次读取与容量扫描完整，2 表示缺失、未知 schema、资源上限或读取问题。它不保证历史结果已经逐项验证，也不保证 worker/API 正常服务。

报告包含应用/Python/schema 版本、近期 worker heartbeat、已有锁的即时观察、各状态实验计数、最多十个失败实验的 ID/状态，以及按固定目录类别统计的文件数和逻辑字节。不会导出原始路径、论文/研究标题、引文或错误正文；需要定位某次失败时，在本机工作台按 ID 查看。

空闲且无 WAL 时，持有已有工作空间维护锁并用 immutable 读取。服务运行时，用只读 SQLite 事务读取已提交 WAL；SQLite 可以通过现有共享内存文件协调读取。缺少可读取的 sidecar/锁条件时返回不可读，也不忽略已提交 WAL。读取期间其他进程退出可能使 SQLite 重新创建 WAL/SHM 协调文件；只读承诺针对业务数据，不承诺活跃数据库的协调文件逐字节不变。诊断不会创建新工作空间。锁状态与 heartbeat 是即时观察，不是进程身份认证。

容量扫描不跟随符号链接，默认最多 100,000 个条目或 2 秒，数据库查询也有时间预算。达到上限明确标记 `complete: false`，不把部分扫描当成全量容量。统计逻辑字节而非磁盘实际分配，硬链接按路径计数，活跃工作区文件大小可能变化。

归档使用既有完整备份/校验/异地恢复流程：停服务、备份、校验后保留清单与原始来源。此版本不支持自动清理或单独删除某次尝试，防止切断问题、审核和回归的历史依赖。
