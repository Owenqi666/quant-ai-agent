# v0.8：安全提交、实验对比与冻结总结

本轮保持本地单用户、合成数据和基础前端。AI 接口、RAG 和 BRAIN 未启用。对比表示保存的评估条件兼容，不能据此认定论文解释、Alpha 有效性或收益改善。

## 创建和执行

1. 启动工作台，导入 Alpha101 示例，或复制已有任务。填写研究标题，检查论文、数据和时间切分并勾选确认。
2. 创建前，浏览器先持久保存完整请求和去重标识。服务端在一个事务中保存研究、初始修订和响应收据。存储不可写时不发送请求。
3. 若提交后响应丢失，刷新页面并打开“新建研究”，通过“安全重试研究创建”确认原结果。即使入口变成空白表单，原请求仍绑定原来的复制草稿；其他草稿保留。同一个请求重试不会创建第二项研究。
4. 提交实验也先保存固定的修订、模式和请求标识。页面刷新后回到相同研究，在“研究工作台”页面安全重试。当前选中修订的变化不会改写原请求。
5. 研究创建重放返回初始创建响应；运行重放确认相同 run 并返回其当前状态。保存成功后的目录刷新失败单独提示，不要求重新创建。

本机草稿和待确认请求位于原浏览器 localStorage，按工作区区分。它们不在服务器备份中。当前按单编辑窗口使用，未提供跨标签页的事务化草稿合并。不要在结果未确认时手动清空浏览器存储；服务器请求收据仍然保留，但页面将失去原请求标识。明确拒绝的请求可解除后修改；409 冲突仍保留原请求供排查。

## 对比两次实验

进入“研究对比与总结”，选择基线和待比较实验。可以跨研究选择，但论文、数据、评估、历史算子和执行语义、数值代码及环境必须已知且一致，才会生成差值。候选表达式变化单独列出，不直接视为评估条件变化。

差值方向为“待比较 − 基线”。每个指标带有 run、attempt、候选、结果摘要、产物标识和 JSON pointer，可下载保存的结果核对。前端不计算金融指标。缺失值不补零；受阻、失败、未知条件、损坏或未验证来源明确显示原因。完整代码版本、预算和工具调用也展示，但不据此推断人工研究效率。

## 冻结研究总结

在当前研究中明确添加 1–20 项实验再生成总结。报告保存所有研究修订及证据归因、所选实验的尝试/失败/事件，以及研究相关审核、问题和回归记录。全研究反馈可能涉及未选中的运行，范围和计数会明确说明；跨研究显式关联的记录列为关联上下文，不默认选中或验证外部运行。

报告获得固定 ID 和内容摘要。JSON、Markdown 从同一个已保存快照导出；后续修订、审核和备份恢复均不改变该报告。每日明细使用准确产物引用，不在总结中重复整份数组。报告摘要验证与原运行完整性验证分别记录。超出明确资源上限会拒绝创建，不静默截断。

## 可复现工程示例

```sh
.venv/bin/python scripts/demo_v08.py --out artifacts/my-v08-example
```

必须使用新目录。此脚本建立独立临时服务和合成工作区：真实提交后断开响应，确认并发重放仍只有一项研究/实验/报告，执行 Alpha006 符号修改，核对非零差值的原产物，验证评估变化不生成差值，追加自动化审核后比较冻结导出，再备份恢复并核对同一记录和导出字节。保存 HTTP 记录、断流证据、比较结果、双格式报告和恢复结果，退出时关闭自己启动的服务。它不写入日常工作区，不产生人工判断或人工耗时。
