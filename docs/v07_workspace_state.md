# v0.7 工作区请求范围与实验监控

本轮保持原有导航和基础界面，将重复的异步范围判断集中到小型 hooks。研究目录、研究选择恢复、版本编辑和导航业务仍由 `App.tsx` 组合，不引入新的状态框架。

## 工作区身份和请求

- `workspaceScope.ts` 保存最近一次成功确认的工作区 ID、单调递增的身份代次、健康请求序号。
- `useWorkspaceHealth.ts` 负责五秒健康探测。短暂网络失败只改变连接状态，保留已确认身份，避免重新挂载正在使用的编辑器或把草稿改绑到空工作区。
- 健康响应只有最新序号可以改变状态。真正的 A→B→A 身份切换仍产生新的代次；旧 A 请求即使 ID 再次相同，也不能更新新 A 的页面。
- 读取、恢复和慢操作捕获请求范围，并在完成时检查范围与 AbortSignal。取消选择或改变身份后，旧读取不会覆盖当前内容。
- App 只把已确认的 `workspaceId` 传入审核组件。具体草稿恢复与待确认提交由审核恢复模块处理。

## 实验监控

`useExperimentMonitor.ts` 统一选中实验的详情轮询、制品加载和事件 feed：

- 活跃实验每 1.5 秒读取；终态或失败后每 5 秒继续检查，保留已有恢复行为。
- 同一实验的手动或审核刷新保留详情组件；不会先清空实验而卸载未保存的审核表单。
- 切换实验、切换工作区或卸载时中止旧请求并清理轮询。详情和制品必须同时匹配实验 ID 与工作区代次才可显示。
- 终态制品按 attempt 读取，新的完成尝试仍会重新加载。
- `useRunEvents.ts` 的 feed 额外绑定工作区代次。即使两个工作区恰好使用同一 run UUID，也会废弃原 cursor 和请求；事件分页、终态补齐与历史查看沿用已有 EventFeed。

## 保持的历史行为

工作区选择依然按真实工作区 ID 分别存储。首页之外的历史研究会按 ID 验证，明确的 404 才回退；临时服务错误保留预期选择并允许重试。浏览器禁止 localStorage 不阻断目录与研究读取。维护范围不包括切换数据源、真实市场验证或身份认证。

## 验证范围

`workspaceScope.test.ts` 覆盖健康失联不换身份、迟到健康响应、A→B→A 代次失效和被取消读取。`e2e/z-selection.spec.ts` 保留原有工作区选择竞态案例，并补充健康失败期间编辑器草稿保留、禁止 localStorage 时启动，以及 A→B→A 返回后的迟到操作。

完整验收还运行已有审核刷新与实验事件流用例。最终计数和结果以新的 release-v07-* 交付目录为准，不能将本文件的计划性描述当成已经通过的测试结果。
