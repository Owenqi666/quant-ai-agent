# v0.11 审核事务与并发测量

审核创建和回归批准现在先在 SQLite WAL 读快照中完整校验输入、实验及产物，再在短写事务中保存业务记录和请求收据。校验大文件时允许其他连接提交实验和更新心跳；同一请求的重放仍返回原记录。

## 保持的边界

读快照保存确切运行状态、研究/修订/论文/数据行、尝试身份、产物登记和（批准时）审核行。文件核验前记录尝试目录的文件清单以及设备、inode、类型、链接数、大小、mtime/ctime；写事务中重新比较数据库行及文件状态。文件变化、替换、增加、尝试变化或来源变化均拒绝发布。文件清单按遍历有界读取，最多 4096 个条目、512 MiB；不重新对全部大文件做哈希。

这是本机不可变产物约定下的变更检测，不是面对恶意文件系统的加密认证。先做完整 SHA256/引擎核验，随后用文件状态检测校验与保存之间的普通本地变化。写数据库锁本身不能阻止外部文件编辑；提交后的漂移仍由既有结果/下载校验发现。同键已成功提交的请求重放承认原提交，不再次写入或冒称重新校验当前文件。

## 可复现测量

```sh
.venv/bin/python scripts/measure_review_concurrency.py --out artifacts/my-review-concurrency
```

每次使用新目录。脚本创建独立工作区，走真实导入、校验、登记和因子计算，生成一份 400 个合成交易日、120 个资产的完成结果。120 个资产由原 12 个合成资产复制扩大文件负载，不能算新增独立研究样本。默认每种操作重复三次，在完整性核验开始时并发发送心跳与新实验提交，保存原始时长和完成顺序，不注入休眠。

优化前证据：`artifacts/v011-concurrency-before-01/measurement.json`。
优化后开发期证据：`artifacts/v011-concurrency-after-01/measurement.json`。
两次均包含约 15 MB 导出产物和相同输入/任务摘要；优化前所有并发写调用在核验结束后完成，优化后测量中所有并发写调用在核验结束前完成。保留了三个重复的全部样本。开发期其他测试可能并行执行，时长包括线程调度、SQLite 等待及提交；不据此宣称稳定的吞吐或百分比提升。冻结后的发布验收还会单独执行本脚本。

## 验证

`tests/test_review_concurrency.py` 通过受控同步点验证校验尚未返回时其他写连接能完成；这种故障/竞态测试与无延迟注入的性能测量分开。覆盖运行状态变化、审核行变化、产物修改后恢复 mtime、增加文件、排队目标拒绝。既有幂等测试继续覆盖同键并发只生成一条记录、提交丢响应、备份恢复、旧尝试绑定、篡改后新写入拒绝和原请求重放。

实际测试结果以本轮验收目录为准，不改变人工审核判断或真实数据执行范围。
