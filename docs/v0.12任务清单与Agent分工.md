# v0.12 工程链路优化任务与分工

起点：v0.11.0 / `6a13f3d`，工作树干净。按“评估 → 清单 → 分 Agent 实施 → 交叉审核 → 冻结源码验收 → 备份更新运行版本”执行。本轮只处理工程线，真实数据、最终市场测试、AI/RAG、BRAIN 和完整 UI 重设计保持后置。

## 审核依据与目标

1. 相关算子在普通自相关中产生舍入差异，截面排名将理论常量变成组合；极端缩放也会错误返回零或缺失。先修数值契约，不对所有因子统一加 epsilon。
2. 修订、问题创建/追加、回归检查尚未完整覆盖提交成功但响应丢失后的刷新恢复。沿用持久原请求与事务收据。
3. 终态实验仍每 5 秒完整读取/核验；领取任务和回归发布仍有耗时文件操作持有写锁。先保存测量，再做针对性优化。
4. 准备输入、计算结束后核验与发布阶段需要持续心跳和精确尝试状态；补关键中断点验收，保留失败文件和旧尝试。

## 独占分工

| 任务 | 负责人 | 写入范围 | 验收 |
|---|---|---|---|
| E1 数值正确性 | 计算 Agent | expressions.py、regression.py、oracle_temporal.py；专属数值测试和说明 | 自相关不形成舍入排名；缩放、负相关、常量、缺失、微小真实差异；旧语义可识别 |
| E2 客户端恢复与读取 | 前端 Agent | frontend/src 的恢复/修订/问题/回归/监控相关文件；专属单测、E2E和说明（不改生成契约） | 丢响应刷新只确认原操作；晚响应/换工作区隔离；终态轻量轮询、显式重新核验 |
| E3 执行阶段与并发 | 执行 Agent | 新 execution_lifecycle.py、runner.py；阶段/故障/并发测试与测量脚本、说明 | 短事务领取、持续心跳、取消和旧尝试隔离；准备/发布中断留痕；测量前后证据 |
| E4 集成与交付 | 主 Agent | service.py、db.py、mutations.py、schemas/API/生成契约、backup/diagnostics、版本、README、集成测试与发布脚本 | schema 迁移与旧记录保留、修订/回归幂等、回归短写事务、统一验收、备份恢复和运行身份 |

E3 通过新模块提供领取/发布/阶段接口，由主 Agent 接入 Store，避免并发编辑 service.py。共享 API 契约由主 Agent 定义并生成；E2 不自行改变接口。Agent 不提交 Git、不操作真实工作区和 8765 服务。

- [x] 保存现有缺陷复现及工程测量；先明确新接口。

- [x] E2/E4：轻量终态状态读取；不把轻量探测当作文件完整性核验，审核和下载继续校验。

- [x] schema 升级/回滚失败测试、备份到新目录恢复验证；旧实验不重算、不改写。
- [ ] 冻结源码，运行统一验收（API、Python、前端、浏览器、基线、独立参考、恢复、源码包安装）。
- [ ] 停旧服务并离线备份；从已验收源码包启动原工作区，检查历史业务行、实验文件和工作区身份。

## 边界与交付

- 历史结果保留其算子版本；新实现不得替旧结果重新背书或把不兼容结果静默比较。
- 同一键重放返回原提交；修改正文必须冲突；服务端已成功但客户端未知不能自动生成新请求。
- 阶段和心跳属于运行可观测性，不能代替结果核验；失败/遗留文件保持可检查。
- 性能结论必须绑定工作负载与原始测量，不承诺实际吞吐改善比例。
- 任务状态、实现说明和正式验收以新发布目录的 `acceptance.json` / `delivery.json` 为准；源码冻结后不回填测试数字。
- 目标版本 v0.12.0；新增收据需要事务化 schema 迁移。若发生迁移后的回退，使用已验证备份恢复到新目录，禁止让旧版本直接打开新 schema。
