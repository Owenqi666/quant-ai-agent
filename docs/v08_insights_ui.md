# v0.8 基础实验对比与研究总结界面

入口是工作台左侧“研究对比与总结”。页面沿用现有表单、表格与详情折叠组件，不改变视觉设计。

## 比较保存的实验

1. 从有界历史目录分别选择基准实验和候选实验，可以跨研究选择；每个选项说明研究、修订、状态和执行流程。
2. 点击“比较所选实验”。结果显示两侧实验、研究、修订、数据摘要、产物核验、条件检查、表达式、候选覆盖、指标和来源。
3. 差值来自服务端读取的已保存结果，方向固定为候选减基准；浏览器不重新计算指标。缺失值显示“未记录”，无法比较的差值显示“—”，不填零。
4. 表达式变化单独展示。未知条件、未核验产物或不兼容条件会阻止差值；可比较也不表示研究语义正确、投资有效或统计显著。
5. 改变任一选择立即清除旧结果并使旧请求失效。请求序号与取消机制避免迟到结果覆盖新选择；A→B→A 也不会恢复旧 A 请求。

指标来源保留 run、attempt、candidate、result digest、产物 ID/摘要和 JSON pointer。覆盖指标和工具调用、记录耗时都按原记录展示，不转换为“提升”或人工研究效率结论。

## 明确选择并冻结总结

1. 当前研究的实验目录支持继续加载历史记录。逐项“加入总结范围”，每份明确选择 1–20 项；可移除，不会自动选中全部历史。
2. 点击“生成冻结研究总结”。固定请求在发送前写入浏览器存储并回读验证；无法可靠保存时不发送。
3. 返回成功后显示“研究总结已保存”，列表刷新独立处理。列表读取失败不会把已保存的报告说成提交失败，固定详情和下载仍保留。
4. 响应丢失或刷新后，在同工作区、同研究页面使用“安全重试研究总结”确认原请求。保持同一 idempotency key 和 run 顺序，不生成新的报告。
5. 明确拒绝的请求可解除后修改。409 冲突或未知响应保留原请求供诊断；不提供忽略未知结果并换键重发按钮。确认后若本机清理失败仍保留原请求安全重试。
6. 每份总结有固定 ID、保存时间、选择范围、记录计数和内容摘要。JSON 与 Markdown 链接始终指向该 ID；之后新增审核不会改变旧总结。需要最新记录时明确生成另一份总结。

报告快照的完整性和原实验产物是否核验是不同事实；报告保留原状态和限制。未提交的选择只保存在当前页面内存，已提交的冻结请求可恢复。浏览器状态不属于服务端备份。

## 作用域与实现边界

- `ResearchInsights` 由 App 按工作区和研究 ID 挂载。切换范围卸载旧组件，旧异步结果不能写入新范围。
- 比较使用独立请求序号；报告列表和详情各自有请求序号。后台同范围刷新不改变固定结果的身份。
- 报告请求恢复键包含工作区、操作类型、研究 ID。其他研究不会读取或重放这份请求。
- 列表默认每页 20 条，可选 1、5、20 条；改变数量会重置到第一页，并使旧请求失效。413 大小限制会明确提示调小到每页 1 条，合法大报告仍可逐项浏览。目录显示明确总数与继续加载，不暗示完整研究。
- 不接入 AI，不自动填写人工评定，不把自动验收记录算作人工研究结果。

## 验证

专属单测覆盖当前研究选择、20 项上限和去重、请求序号失效、缺失指标与差值显示。真实浏览器场景使用新建临时工作区和自有 API/worker，验证实际计算后的对比及报告恢复和冻结性。开发运行日志、截图与失败记录保存在 `artifacts/v08-insights-ui-development`；最终计数以统一发布验收目录为准。
