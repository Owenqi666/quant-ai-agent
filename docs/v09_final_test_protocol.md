# 最终测试流程：实施规范与前置条件

状态：设计完成，执行入口尚未实现。普通任务仍只在 validation 上迭代，既有 test 隔离检查保持有效。本文件不是最终测试已执行的证据。

## 两种保留评测必须分开

1. 研究任务保留集：未参与开发的论文、任务和预先冻结的人工判断，检验证据、归因、字段及实现流程。不能把 Alpha101 的新窗口变体当新论文。
2. 市场时间保留区间：同一个研究任务从未用于候选选择的 test 日期，检验冻结候选的区间外结果。得到该区间的结果也不能声称已实现成交、费用或容量模型。

v0.9 的材料准入检查只核对声明完整性与文件摘要；它既不认证使用权，也不验证经济判断。真正执行前必须选定具体材料、授权数据及评价规则。

## 必须先冻结的内容

- 协议 ID/版本、创建者声明、选择候选的依据和研究目的；所有已尝试候选及被弃理由的索引。
- 原文和证据、候选集合及表达式语义、数据/元数据快照、字段映射、历史股票池、交易日历、复权和可得时点规则。
- 开发区间与最终区间边界、标签跨度、预热历史、跨边界剔除规则、最小截面和缺失处理；测试区间不能参与阈值、标准化、候选或参数拟合。
- 引擎/算子版本、可重建代码摘要、运行环境和资源预算；指标集合、比较基线和判断标准必须在读取测试结果前指定。
- 保留研究任务清单、人工预期和独立参考的支持范围。未覆盖的表达式标为不可比较，不能用生产计算路径给自身盖章。
- 允许的失败恢复、结果披露规则、后续研究的隔离方式。以上变更必须产生新协议，不能覆盖旧记录；已披露后的新协议不得把相同区间重新称为未见测试集。

## 状态与数据结构

| 状态 | 允许操作 | 持久记录 |
|---|---|---|
| draft | 编辑协议、验证前置条件 | 可变草稿，尚无 test 权限 |
| frozen | 核对完整材料、显式提交或撤销 | 不可变协议/候选/输入摘要、原始声明 |
| submitted | 排队、提交原请求重放 | 唯一 logical_evaluation_id、请求摘要、预算 |
| running | 监督进程、保存尝试及暴露事件 | attempt_id、worker 身份、心跳、事件、输入快照 |
| completed | 只读核验和导出 | 原始产物、指标引用、完整性结果、披露时间 |
| failed / interrupted | 按冻结协议恢复，或停止 | 失败原因、是否可能已计算/披露、恢复决策 |
| quarantined | 不发布结果，人工排查 | 输入漂移/摘要不符/归属冲突/非法恢复 |

建议新增单独的 final_protocols、final_evaluations、final_attempts 和 append-only final_events，不将普通 run 的 split 字段变成任意 test 开关。客户端不拥有解除数据边界或重新标记未见区间的权力。

## 一次性与恢复的准确含义

“一次性”约束一个冻结研究协议下的逻辑提交与正式结果披露，不承诺操作系统只执行一次算术。数据库原子事务约束协议、候选集合和提交键；同键同正文重放同一逻辑评测，异正文返回冲突。并发提交不能多消耗预算或产生多个已发布结果。

提交前验证所有摘要。运行前再次核对当前冻结输入；任何漂移隔离。工作进程故障后可以按既定预算对完全相同输入恢复，但每次 attempt、失败和可能发生的结果暴露必须保留。已经看到最终结果后改参数或换候选，不属于恢复，应成为明确标注“已见该区间”的新研究。

结果写入与发布分开：先持久原始产物，核对运行/尝试/输入归属，再原子登记发布摘要。响应丢失只重放原记录；不能重算并覆写首次发布。损坏产物停止导出，不根据旧摘要继续展示成功。

## 与现有回流的连接

- 复用既有不可变研究修订、预算、队列、快照、产物摘要、幂等收据与备份设计；新协议需独立数据库迁移和完整契约测试。
- 研究总结可以引用最终评测，但必须标明已披露及时间；普通开发对比、回归样本生成和未来 AI/RAG 默认排除最终保留答案。
- 人工流程耗时与金融结果分开保存。审核意见不自动修改冻结候选；新的观察作为后续研究材料，不能倒填原先的选择理由。
- 当前合成数据只能用于故障注入和边界软件测试，不能填成真实市场 test 研究结果。

## 实施前置清单与顺序

1. 明确一份授权数据及语义，完成来源专属适配器和时间对齐验证。
2. 明确独立研究材料与判断标准，覆盖计划提交的关键公式及负例。
3. 由研究者冻结以上协议，确认该保留区间是否已经看过。不能靠代码扫描证明“从未看过”。
4. 实施数据库状态机、逻辑提交和失败恢复，再实现受限 worker 入口与前端只读结果。
5. 在独立合成工作区做完整故障验证；通过后才对冻结真实输入正式提交。

## 必须覆盖的验收场景

- 普通任务试图设置 test，仍拒绝；测试数据值/未来日期不得进入开发指标、阈值拟合或候选选择。
- 冻结后更改候选、公式、数据、配置、代码或环境，提交失败且原协议保留。
- 并发同键、响应提交后断开、重启后重放，只有一项逻辑评测和一次正式发布。
- 确定未执行、执行中、结果已落盘未登记、已登记未返回四种故障分别恢复，尝试历史不丢失。
- 预算耗尽与无支持的独立数值参考明确停止，不静默降级成正确。
- 跨区间标签/预热边界用可手工核对的数据验证；最终区间改动不得影响此前 validation 结果。
- 已披露区间不能因复制协议或更换提交键变成“未见”。
- 摘要不符、错误 attempt 身份或原始产物丢失，不展示/导出成功数字。
- 备份到新目录恢复后，逻辑提交、暴露标志、原结果字节及幂等行为保持。
- 报告数字定位到实际原产物；研究者观察和自动化测试证据保持分离。
