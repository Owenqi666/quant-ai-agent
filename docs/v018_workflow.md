# v0.18：受控研究执行与精确结论引用

本轮在现有工作台中接通日度本地研究执行。模型接口未连接，页面沿用基础设计。无需新依赖；首次安装步骤见 README。已安装环境启动：

```bash
.venv/bin/python -m paper_alpha.server.launcher --home var/workbench --port 8765
```

## 完整例子

1. 打开工作台，必要时点击「导入示例研究」。Alpha101 材料来自用户使用过的研究论文；示例市场数据仍为合成数据。
2. 左侧选择「研究执行」，展开「创建一次研究执行」，选择 Alpha101 研究，仅勾选 alpha101 候选，创建一次任务。
3. 依次点击「校验候选草稿」「保存已校验的研究修订」「提交冻结实验」。背景 worker 计算；等待按钮「核对本次实验」可用后核对，再点击「完成研究执行」。
4. 点击「打开本次实际输出与审核」，查看原计算结果、图表、数据覆盖和失败诊断。审核必须由实际评审者填写，不因程序执行成功自动成为人工批准。
5. 返回「研究执行」并选择任务，点击「关联到研究任务」。在详情中展开「带实际数值引用的结论草稿」，填写待审核解释，核对指标引用，再保存草稿。首项默认指向 `/0/result/metrics/mean_rank_ic`；不同结果按完整输出选择其允许路径。服务生成实际数值显示，用户不上传数值。
6. 下载执行记录、研究任务和结论引用记录。后续修订仍经同数据保留区间检查；原最终 test 不可改名为开发区间。

页面默认任务最多 12 个研究步骤、2 次技术失败、300 秒总墙钟时间；预算闭合后另允许 1 条安全停止记录，包含操作、排队及计算等待。API 可显式设置有界预算。超时后任务不能自行增加预算；创建新的用户任务也不会移除测试区间保护。候选缺字段、证据失效或方法未决时保留阻断；若允许部分候选，必须创建时明确勾选并保留排除诊断。

响应丢失时使用「安全重试」确认原持久请求，不能把未知结果视作未提交。刷新不会重置预算或再创建修订。取消和恢复行为详见执行契约。

## 可复现工程验收

每条命令使用一个新输出目录，避免覆盖历史证据：

```bash
.venv/bin/python scripts/demo_v018.py --out artifacts/my-v018-example
.venv/bin/python scripts/evaluate_v018.py --out artifacts/my-v018-evaluation
.venv/bin/python scripts/export_api_contract.py --check
.venv/bin/python scripts/verify_release.py --out artifacts/my-v018-release --browser-channel chrome
```

脚本对比同条件的固定计算流程和受控执行路径，并检查拒绝、归因、引用和恢复。它不模拟 LLM 效果、供应商费用或人工耗时改善。语义材料与真实人工确认步骤见 `docs/v018_evaluation.md`；未确认标签保持 pending。

## 边界

- 原始论文文本和公式、用户修改、项目约定、模型推测分别归因。引用身份正确并不证明解释忠于原文。
- 新研究任务可冻结已有五维审核。旧 v17 任务缺少这些字段时保持历史未知，不回填或改变原摘要；后来审核需在原结果页查看或新建快照。
- 可信数值限定为服务解析的精确结果字段。叙述中的数字仍属于未经审核的文字。
- 时间保护按已核验市场 CSV 内容识别数据；历史潜在暴露也保留。改变输入内容后属于新数据版本，需用户重新确认来源与时间语义，不自动取得独立最终测试资格。
- 日度任务调度已接原队列；月度和作者准入模块可读入研究任务、评审、结论，但本轮没有把作者阻断转成可执行组合，也没有接通跨路径自动调度。
- 这是单用户本地系统，不声明多租户鉴权、云部署或远端 CI 已验收。
