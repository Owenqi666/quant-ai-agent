# v0.6 任务清单与 Agent 分工

起点：本地 `v0.5.0` / `a15d613`，工作树干净。2026-10-01。

目标：让研究质量判断、输入数据错误和独立数值核验有明确且可检查的结构。继续单机单用户、基础前端、确定性工具链；AI/RAG/BRAIN 和真实行情接口保持当前边界。

## 分工与文件所有权

| 负责人 | 独占范围 | 交付 |
|---|---|---|
| 研究审核 agent | DB 迁移、审核服务/输入模型、新研究审核模块、API 响应模型及专属测试 | 版本绑定的结构化审核和显式主动工作时间记录；旧记录保持未评定 |
| 数据诊断 agent | loader 输入校验、导入验证器、新诊断模块及专属测试 | 稳定错误码、行列/日期/资产定位、有界错误样本，计算与导入共用校验 |
| 数值核验 agent | 独立参考、专属测试、v06 开发任务集 | 少量明确登记的新增组合、独立因子/标签/权重/汇总复算及负例 |
| 主 agent | 前端集成、生成契约、汇总指标接入、备份/诊断兼容检查、版本、公共文档和验收脚本 | 最小表单操作、分层结果展示、真实 HTTP 示例、冻结与交付 |

`response_schemas.py` 由审核 agent 统一写入。数据诊断 agent 先交接诊断 JSON 形状，主 agent 在后端契约冻结后生成前端类型。源码目录共享，不以平行编辑同一文件替代协作。

## 执行顺序

1. 固定审核与诊断契约，三个 agent 并行实施；主 agent 准备表单与验收。
2. 后端冻结后统一生成 OpenAPI/TypeScript，接通前端、反馈汇总和真实 HTTP 示例。
3. 独立交叉复核有业务意义的错误路径，修复后按所有权冻结。
4. 新建 `artifacts/release-v06-*`，完整验收并保存失败证据；最终任务状态另存交付目录。
5. 版本交付时备份旧工作区，恢复到新工作区后核验历史实验；不原地覆盖旧记录。

本轮不以重构整个 App 或引入框架为目标；将新增审核逻辑放入独立组件/纯函数，并对实际触及的异步状态加范围保护。性能优化等真实 HTTP 测量出现瓶颈后安排。

## 研究评价边界

Alpha101 是用户确认使用过的开发材料。新公式改动必须如实归因，不把经济解释写成论文证明。自动化样例记录来源 automation；只有用户实际参与后的记录才可能是人工研究评价。主动计时只是显式记录的观测，不自动形成“节省时间”结论。最终市场 test 区间继续隔离。

## 集成复核记录

- 新审核表单拆成独立组件，保存成功与刷新失败分别处理；同一实验刷新保留未提交审核及计时，批准回调核对导航代次。专项 Chrome 测试覆盖这些实际异步缺口。
- 数据诊断复核发现旧 parser 允许 quoted 数值闭引号后的空格/tab，增加兼容用例并继续以原 pandas 解析为权威。NUL 截断及额外隐式索引列的静默丢弃有意改为拒绝，协议明确说明。
- 源码包首次集成测试因新目录未包含在测试夹具中失败；改为与已有用例相同的逐文件白名单，7 项打包测试随后通过。原失败保存在 artifacts/v06-development。
- 开发期间本地 8765 预览运行已验收的独立 v0.5 源码，避免中间构建与旧后端不匹配；最终验收后才迁移至新工作区。

上述为冻结前开发检查，不替代 release-v06-* 的正式验收。
