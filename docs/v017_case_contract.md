# v0.17 研究上下文、结果身份与更新规则

ResearchCase 把一个已有计算结果整理成可查看、可引用的研究上下文。它不创建实验、不修改研究计划，也不把建议转换成批准。当前支持 `daily_run`、`monthly_experiment` 和 `author_study` 三类来源，各自仍由原来的服务负责计算和核验。

## 内容与依据

| 字段 | 保存什么 | 解释边界 |
|---|---|---|
| `source_kind` / `source_id` | 原始领域及资源身份 | 同一篇论文的月度实验与作者数据准入仍是不同来源 |
| `evidence` | 证据 ID、来源类别、定位、文本、核验类型 | 逐字引用核验不等于语义忠实性评审 |
| `definitions` | 已有假设或计划定义、归因、证据 ID | 保留论文原文、用户修改、模型推测或项目约定的区别 |
| `data_scope` / `method_scope` | 本次结果实际使用的数据和方法范围 | 不把受控示例收益归到作者文件 |
| `provenance` | 输入、配置、代码、结果与原始记录的身份信息 | 未建立的来源属性不推断为已核验 |
| `results` | 工具生成的结果身份、摘要说明、内容哈希及规范 JSON | 页面与报告引用这些结果，不接受模型填写统计数字 |
| `reviews` | 创建时已有的审核身份、行动者声明、决定、原始适用范围及备注 | 审核是历史快照，不向新结果继承批准 |
| `state` / `stop_reason` / `allowed_actions` | 当前结果对应的诊断状态及允许建议 | 允许建议不等于授权执行该行动 |

`evidence.verification` 有三类：

- `literal_quote_verified`：daily 路径已从冻结 PDF 核验页码和引文文本；仍需单独判断假设是否忠于引文。
- `source_registry_reference`：引用现有来源登记及定位信息。Momentum 的论文或作者代码解释属于这类，不冒充本次重新完成的逐字核验。
- `project_declaration`：项目采用的窗口、缺失处理、筛查或实现约定。它们不能被归因为论文已经确认的方法。

已有 daily 假设保留其结构化归因。月度路径展示冻结的协议，作者路径展示冻结的准入计划；后两者尚未形成独立的“新假设创建—证据审核—候选实现”工作流。

## 精确结果绑定

一次上下文创建经过两步：

1. `preview(source_kind, source_id)` 调用原服务核验结果，计算 `source_digest`。
2. `create(...)` 携带这个 `source_digest`，再次核验并冻结。如果预览后结果或纳入的审核发生变化，创建请求返回冲突，要求重新预览。

`source_digest` 是 `{source_kind, source_id, context}` 的规范摘要。Case 自身的 `id` / `digest` 还绑定标题、备注及上述内容；创建时间另有元数据摘要。

不同来源的结果绑定如下：

| 来源 | 原始绑定 | `results` 中的内容 |
|---|---|---|
| `daily_run` | 已完成并核验的 run、revision、attempt、完整 state 摘要、manifest 与代码摘要 | 已核验候选的公开投影，保留表达式、归因、错误和指标，省略完整 daily 明细；投影摘要与完整 state 摘要分别记录 |
| `monthly_experiment` | 已完成并核验的 experiment、attempt、输入、协议、配置、result、manifest、代码及环境摘要 | 原月度工具的完整规范结果，包括受控数据身份、分组、权重、收益与费用代理值 |
| `author_study` | 不可变 study、输入 scan、计划、筛查结果、父研究/审核身份 | 聚合准入计数及其依据；HTTP 只核验聚合一致性，不重新读取 MAT |

每次读取 Case 都重新调用来源完整性核验。结果文件、绑定的 attempt、冻结审核或 Case 元数据被改变时，读取拒绝返回可信上下文。它不会自动改绑到最新实验结果。

## 审核和快照如何更新

Case 不提供原地编辑接口。原研究新增审核后，旧 Case 继续保留原来的审核集合；读取时逐一核验这些旧审核仍对应原始结果。新增审核不会让旧 Case 失效，也不会偷偷出现在旧快照里。

要查看更新后的审核上下文，应重新预览同一来源并创建新的 Case。要更改计划或方法，应先在原领域界面创建明确的新版本并得到新结果，再为该结果创建 Case。新 Case 不代表旧批准适用于新结果。

工具会话绑定固定 `case_id` / `case_digest`。重新打开同一会话保留原调用预算、错误与记录。新快照需要显式创建新会话；受限工具本身不能新建会话或补充预算。历史幂等重放返回原调用记录，不代表重新执行了当前来源核验。

`actor=human` 或 `automation` 是本地行动者声明，没有提供账户认证；自动化建议固定为 `automation`、`draft`、`semantic_fidelity=unverified`。

## 状态和下一步

| 结果 | 状态 | 允许提出的下一步 |
|---|---|---|
| daily 至少有一个候选完成评估；月度结果 evaluated/partial | `ready_for_review` | 请求人工审核、建议显式修订计划 |
| 作者筛查未达门槛；月度没有可评估时期；daily 候选全部受阻 | `data_insufficient` | 停止数据不足候选、请求审核、建议显式修订 |
| 作者准入通过但没有组合实现；论文月度规则未解决 | `rules_unresolved` | 补齐方法、请求审核 |
| 已完成 daily 尝试没有可评估候选且包含非数据失败 | `implementation_failed` | 请求审核、建议修订 |

一个研究可以同时包含成功和失败候选；`ready_for_review` 仅表示有结果可供审核，不表示全部成功或研究已获批准。工具成功返回 `data_insufficient` 是正常诊断结果，不应触发无界错误重试。

## 比较两个 Case 之前

本轮没有新增跨 Case 的自动兼容性判定或收益汇总工具。共同的字段结构和相同论文题目不能证明两个结果可直接比较。

比较时应核对：研究问题及信号定义、来源和数据版本、样本范围、形成期与持有期、缺失规则、标签覆盖、算子语义、组合和费用方法、开发区间、计算代码以及指标定义。变化的项目必须在比较说明中列出；不能在改变样本或门槛后把更好的数值直接归因为策略改进。

固定脚本与受限工具对同一 Case 的对照，验证的是读数和决策流程的一致性。它不是两项独立量化研究，也不证明 AI 增益、人工耗时下降或市场收益改善。

## 本轮仍未支持的能力

- 作者月度文件到组合排序、权重、持有收益的完整输入适配。`screen_passed` 始终不等于 `execution_ready`。
- 新论文的自动检索、语义证据判定，以及自动新建假设或候选实现。
- 在工具中导入模型生成的计数或指标，代写人工批准，自动降低门槛，运行任意代码或访问最终测试。
- 研究系列级最终测试开放机制、真实市场绩效结论和完整论文复现。

这些边界同时保留在上下文、工具能力表及评测报告中。对未实现能力的自然语言提议仍然只是待审核文本。
