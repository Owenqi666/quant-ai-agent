2. **审核事务并发验证（并行实施）**：审核和批准当前在 SQLite 写事务内验证结果文件。先保存可复现的并发写等待测量，再据证据优化；不得预先声称实际故障或性能提升。
3. **单来源真实数据适配（需要输入）**：仓库现有示例和导入执行契约是 synthetic-only；已有真实数据准入工具只检查声明与摘要。确认来源、授权范围、样例及时间规则后，实施来源专属转换与独立校验。没有真实来源时不伪造数据、不仅通过删除 synthetic 限制开放执行。
4. **实际研究覆盖与最终 test（依赖阶段 3）**：按真实候选扩充独立参考，再按已有 v09 最终测试规范实现冻结和披露流程。当前最终 test 继续隔离。

## 图表正确性契约

- 请求明确指定 run、candidate、attempt 和 result_digest；返回冻结 revision、结果产物摘要、数据版本及评估区间。候选切换后迟到响应不得覆盖新图。
- 第 1 组：每日毛收益及有效日毛收益的算术累计。累计不称复利净值或 BRAIN PnL；未扣成本，不能据合成数据宣称投资价值。
- 第 2 组：每日 Rank IC。未定义 IC 保留 null 及原因；不能补零。
- 第 3 组：每日有效资产覆盖和跳过状态。purged 日期的初始化零不是实际零覆盖，应显示不适用。
- 收益按 exit_date 表示完成持有期；保留 signal/entry/exit 日期。IC 明确对应信号及其后续持有期。
- 累计只增加已评估日，未评估日留空和断线；保留真实零值。没有有效结果时显示原因。
- 图表只读取已核验产物；失败、过期目标、摘要不匹配、无计算产物分别返回明确状态，不回退到其他候选或最新尝试。
- 不给出自动投资“通过/优秀”标签。Sharpe、资金净值回撤、换手、扣费后收益需要新增评估语义和工具结果，留在后续阶段。
- 不把所有逐资产明细塞回普通 run 响应。新接口有大小/点数限制，不静默截断。
