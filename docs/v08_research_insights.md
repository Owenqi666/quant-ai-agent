# v0.8 实验对比与冻结研究总结

## 用途与范围

本模块读取已保存的研究和实验，回答“这两次实验改变了什么”和“这一研究当前有哪些可检查的证据与过程”。它不生成新因子，不重跑金融计算，不使用 AI，也不推断人工研究耗时。

后端入口为 `ResearchInsights(store)`；HTTP 与基本界面由工作台集成。数据库 schema 6 新增 `research_reports`，报告正文和请求收据同一行原子保存，不另建外部报告文件。

## 对比

`GET /api/run-comparison?baseline_run_id=...&candidate_run_id=...` 可选跨研究的两个历史运行。输入顺序有意义，指标差值一律是 candidate minus baseline。

1. 对两次实验使用同一个 WAL 只读数据库快照。复用现有源产物校验，核对当前 attempt 的原始 state、manifest、输入、源代码、工具记录、结果与导出产物。昂贵文件核验不持有 SQLite 写锁。
2. 从核验过的历史 Python 源文件安全解析字面量算子和执行语义，不执行历史代码，也不使用当前代码常量填补历史缺失。历史语义无法解析时标为 unknown。
3. 检查论文摘要、数据摘要和元数据、时间切分及评估配置、历史语义、数值执行及输入依赖的源码摘要与运行环境。指纹包含 worker 的时间裁剪/对齐、workflow、输入契约和 CSV/存储依赖，不能只比较 evaluator 或语义常量。代码声明必须绑定已核验的 source 快照文件；Python、平台及已定义依赖版本缺失时标为 unknown。任何未知或变化都会阻止指标差值。完整代码摘要、修订、预算和运行模式单独展示；非数值服务代码变化本身不阻止比较。
4. 按候选 ID 对齐，保留新增、删除和失败候选。表达式变化是比较对象。两侧候选都必须 evaluated，且结果产物可定位并匹配原保存结果，才能对有值的指标计算差值。缺失值不填零；阻止差值时仍可展示已单独核验的单侧值及原因。
5. 每个指标包含 run、attempt、candidate、完整结果摘要、结果产物 ID、原始与下载产物的 SHA-256、JSON pointer。数值仅来自保存的计算结果。

“条件可比”只表示上述记录相容，不表示经济含义忠实、策略优质、统计显著或真实市场收益。覆盖率和有效天数可能因表达式而改变，必须与均值一起审阅。工具调用数和 elapsed_seconds 是引擎记录，不是人工效率测量。

## 冻结研究总结

- `POST /api/researches/{id}/reports`：`{run_ids, idempotency_key}`，明确选择 1–20 个不重复、属于该研究的 run。顺序进入请求指纹，同一 key 和正文返回同一个原报告；不同正文返回 409。并发确认只落一行。
- `GET /api/researches/{id}/reports?limit=20&offset=0`：返回 items、total、limit、offset。limit 为 1–100。
- `GET /api/research-reports/{id}`：返回固定报告及其 payload。
- `GET /api/research-reports/{id}/export?format=json|markdown`：从相同持久 payload 导出。JSON 是完整报告 envelope；Markdown 同时包含简要索引和完整 payload 的 JSON 区块。

报告记录明确选择的运行及全研究上下文：

| 内容 | 范围 |
|---|---|
| 研究、论文、数据身份和版本 | 该研究 |
| 修订、论文引用、假设和归因、表达式 | 该研究全部修订 |
| 候选及失败、candidate attempts | 所选运行的当前 run attempt；不把历史 attempt 候选细节静默合并为当前结果 |
| run attempts、错误、事件、产物引用 | 所选运行的全部历史；旧 attempt 的候选全文仍可通过其 state/result 产物引用读取，本报告不重新核验旧 attempt |
| 审核、问题及其追加历史、回归案例和回归检查 | 该研究全部反馈，包含未选运行；另冻结 issue 显式链接的外部检查、所含检查引用的案例及其原审核 |
| daily 明细 | 不重复写入；记录精确行数与完整结果产物引用 |

报告含各类计数、未选运行数、外部关联反馈数和没有当前目标审核的候选数。外部关联记录保留自己的研究/运行身份，不自动加入所选运行或宣称源运行已核验。不把 automation、imported、legacy_unknown 审核变成人工结论；未审核与未执行状态保持可见。旧回归案例的空 contract 和旧审核的空 assessment 原样保留。

每个源运行保留 capture 时的 source_verified 和具体核验错误。源产物缺失或损坏的运行仍可进入报告，其失败过程仍保留，金融指标则不作为已核验结果导出。报告自身 integrity=verified 只验证冻结 JSON 摘要与身份、请求绑定，不代表所有源运行都通过核验。

报告冻结一个一致的数据库读取视图，文件核验在读取期间发生；snapshot_at 表示捕获视图的时间。捕获后新写入的审核和事件不会进入旧报告，提交前也不会把它们拼入旧视图。此设计允许运行队列与审核继续写入。创建请求重放校验原报告，不重新生成或重新检查现在的源产物。

路径脱敏在持久化前完成。备份恢复复制固定报告正文，恢复后的同 ID JSON/Markdown 下载字节不变。下载时验证 payload SHA-256、schema、报告/研究/创建时间身份和原请求指纹；异常返回 409，不输出部分内容。SHA-256 是一致性检查，不是防拥有数据库写权限者篡改的签名。

## 明确资源边界

- 单份报告最多 20 个运行、100 个研究修订。
- 每一类关联查询最多 5,000 条；单次运行事件及研究 issue events 最多 10,000 条；各查询累计文本最多 32 MiB。
- 单个源 state 最多 32 MiB；单运行原始文件核验最多 3,000 文件、256 MiB。
- 冻结 payload 最多 24 MiB。
- 超过任一源/报告限制返回 413，不截断并冒充完整报告。输入重复/越界返回 422。报告目录使用明确分页，每页校验累计正文亦受 32 MiB 限制，超限时缩小 limit。

当前界面以本地单用户、小规模研究为目标；上限不是已完成容量压测的结论。全部每日结果仍可经实验产物下载入口检查。

## 验证

专用测试 `tests/test_research_insights.py` 使用真实 Alpha101 engine、SQLite 和备份恢复，覆盖实际表达式改动的有源差值、配置阻断、候选增删、损坏/缺失产物、未执行与失败、历史源码语义、冻结报告及反馈、并发重放、恢复字节一致、哈希异常、范围上限及读取期间并发写入。统一发布验收与浏览器场景由主任务执行，最终数字以新发布目录为准。
