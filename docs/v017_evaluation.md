# v0.17 研究判断与受限工具评测

本轮评测验证工程规则与权限边界。它不提供人工语义真值，不衡量模型优势、研究人员节省时间或真实市场表现。

## 先声明预期，再接实现

固定材料位于 `evaluation_suites/v017/manifest.json`。清单在执行器接入前冻结，包含十项规则：结果对应、数据不足停止、证据身份、归因边界、越权拒绝、指标注入拒绝、不允许的下一步、幂等重放、重启预算、提案与批准分离。

`ground_truth.semantic_fidelity` 保持 `pending_human_confirmation`；审核者与确认时间为空。实现通过规则检查不会将这些字段改成人工通过。人工后续应分别检查引用是否支持结论、项目约定是否合理、停止决定是否与研究问题一致；这些判断不得从程序测试通过推导。

## 两条明确区分的示例

成功路径使用既有月度引擎的完整受控数据：固定项目规则、2025 年 1–2 月、成本参数 5 bps、最少 18 个资产。正式工作流实际计算并通过已有独立数值参考校验，再绑定统一研究任务。任务建议为请求人工审核；演示不会代写审核。

阻断路径使用显式合成聚合扫描文件 `blocked_scan.json`：两个开发月份分别只有 5 和 8 个 MOM 可用资产，预先声明门槛为 30。工具应解释数据不足并提出停止，不能执行作者源组合、降低门槛或生成新的计数。文件中的来源标识只服务于既有契约校验，不能证明原始 MAT 扫描已经发生。

演示可通过 `--input` 指定已有扫描产物。输入须满足既有扫描契约且实际筛查为阻断；扫描原件会冻结保存。该选项不重新扫描 MAT，也不赋予 API 原始来源认证能力。固定评测始终使用已冻结的合成输入。

## 对照与可追溯性

固定流程直接使用与工作流相同的输入计算结果，脚本策略从绑定该结果的受限工具会话读取并提出预先声明的动作。对照检查输入、计算结果与动作是否一致。共享引擎的一致性是集成证据，独立数值正确性仍由既有 Fraction 参考检查提供。

每次运行必须写入全新的输出目录，保留固定清单、输入、来源工作区、来源计算产物、任务、会话、逐项断言和汇总报告。失败时也保留已完成记录并写入失败状态，不覆盖之前的运行。报告数字来自保存的检查结果；不会填充人工耗时、模型调用成本或不存在的语义评分。

预算恢复检查使用新的 Python 子进程读取已保存的会话，消耗剩余调用次数，再确认超额调用被拒绝。子进程退出码和输出另行保存。它验证正常进程重启后的持久性；执行中异常退出、锁释放及保守扣费由工具模块的专门测试覆盖。

## 运行

```bash
.venv/bin/python scripts/demo_v017.py --out artifacts/demo-v017-01
.venv/bin/python scripts/evaluate_v017.py --out artifacts/evaluation-v017-01
# 可选已有阻断扫描；不重新认证原始 MAT
.venv/bin/python scripts/demo_v017.py --out artifacts/demo-v017-source-01 --input path/to/scan.json
```

以上命令只创建隔离工作区，不操作运行中的工作台。真正 HTTP、浏览器交互及发布迁移由发布验收另外覆盖。

## 验收边界

本轮适用于提供商尚未接入的研究诊断与提案接口。新假设生成的语义审核、真实作者源组合计算、研究系列级最终测试控制、真实人工工作流效率和 LLM 对照仍需后续完成。
