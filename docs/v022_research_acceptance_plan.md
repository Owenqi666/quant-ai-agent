## 1. 人工验收材料的操作链

1. 只读获取已冻结 Case、准确 Claims、单条 ClaimReview target 和已有审核状态，确认全部 ID、摘要、来源、结果与收据一致。
2. 将目标支持的原始来源投影成白名单 source ID。HTTP 接收 case/claim/source ID 和准确目标摘要，不接收文件路径、URL 或任意代码。
3. Alpha101 从已核验日度输入取得原 PDF；行业 MOM 从自己的已注册来源副本取得归档 PDF / 方法等受限文件。每次打开都复验准确来源与目标，拒绝漂移、错域、未知 source ID、链接与超限文件。归档作者代码只作为阅读材料，不执行。
4. 在原准确审核页面增加最小的来源查看/下载连接，沿用现有表单和布局；不另做完整 UI。
5. 新只读 CLI 将上述材料导出到新目录，保存 manifest、准确目标、来源文件、工具输出和短阅读说明。五维判断为空，不预填 reviewer、时间或通过值。离线核验必须发现任何来源/目标/输出漂移。
6. 为现行 Alpha101 与行业 MOM 各准备一份真实材料包；后台和现行工作区不写入真人判断。用户在已有审核入口填写，结束后再核对保存记录及冻结参考。

## 3. 研究评测范围扩展

采用独立、可扩展的 **研究评测样本包**，复用 Case / Claims / ClaimReview 的准确身份，不改写旧七项语义材料、旧标注和旧参考集，也不将所有论文当成同一种计算域。

### 共享输入与身份

- 样本绑定准确 `case_id/digest`、`claims_id/digest`、`claim_id`、`target_digest`，并保存经过服务核验的 Case / Claims / target 投影和 source 文件清单。
- 可支持实际日度 Alpha101 与行业 MOM 两个域；其他已有域必须明确支持或明确拒绝，不强转结果。工具值仍引用具体 result ID、result digest 和 JSON pointer。
- 本轮输出主体只能是实际存在的 automation 草稿。未来模型经相同 ClaimDraft 合同接入后可形成新样本，但本轮不得标为已评测 LLM；文本 execution_reference 或调用来源自述不是实际模型调用证明。
- 样本、参考快照和评测报告以不可变目录及摘要绑定；保存输入、运行实现/版本、配置、检查结果、错误和原始引用。已有文件不覆盖。

### 技术检查与语义参考

1. 对输入结构、来源/目标/结果绑定、引用成员、归因、实际指标 pointer 与数值一致性执行确定性检查，数字直接来自工具输出。
2. 来源完整性检查与独立数值参考、再次运行复现是不同证据；不以文件存在宣称计算已复现，不把结构通过当作研究忠实度通过。
3. 真实人工参考只来自服务中经复验、绑定同一准确 target 的 ClaimReview。保存全部选定/活动人类记录及 ID/摘要，保留冲突、未知与取代历史；无人工记录不制造参考。
4. 只有明确存在可比较的参考和预测判断才计算声明一致性，且不得命名为模型准确率或客观论文正确率。当前只有草稿和没有预测时，语义与模型质量保持待评测。
5. 报告分列软件合同检查、源/指标核验、人工参考覆盖、模型执行状态和限制，保存失败样本与不可比较原因。
6. 固定回归案例至少覆盖：真实形状的两个域、过期 target、跨域/跨结果 pointer、错误数值、缺文件/篡改、人工记录与 automation 隔离、无标签、未知/冲突、报告数字对应工具值、输入恢复后一致。受控测试标签只进入隔离临时目录。

先完成可复用包与工具，再把实际服务中生成的两份审核材料包接入。真实数据的技术验收、固定测试的预期结果和真实人类结论分别记录。

## 7. CI 和交付整理

1. 保留现有 GitHub Actions 完整验收与失败证据上传，补查权限、并发、资源时间预算及干净工作区行为，不依赖本机 artifacts、var 或第三方真实市场文件。
2. 实现/完善本地远端准备检查：确认仓库 remote、CI 所需文件、锁文件、版本与包清单、源码私有材料边界；不读取或输出 token / 凭据，不推送、不新建仓库、不公开发布。
3. 新增工程工具/文档必须进入源码包；新环境仍能安装运行，第三方行业原材料继续需要操作者单独注册。
4. README 用一个当前能力表区分日度合成、受控月度、真实行业修改案例和作者准入诊断，更新运行与研究验收的当前入口。旧计划/历史报告属于冻结快照，不改写绑定材料或旧成果；用当前交付索引明确最新状态。
5. 远端仓库地址已作为缺失信息询问用户。本地配置和预检先完成；只有用户给出目标并具备适当访问方式后，才执行对应远端工作。未运行时记录 remote_ci=not_run，不能以本地门禁替代。

## 集成、测试与发布顺序

1. 原工作台继续运行已验收 v0.21 包；并行实现仅使用各自临时工作区和独占文件。
2. Agents 尽早交付合同，依赖合同顺序接线，不让尚未定义的字典变成隐含接口。
3. 专项必要测试 → 交叉审查负例 → API 合同生成/兼容 → 前端 typecheck/build 与相关浏览器场景。
4. 在隔离副本复验真实 Alpha101 / 行业 MOM 只读材料和研究样本，记录 original manifest、现行人工记录、旧案例/结果和保留区间均未变化。
5. 固定新版本及源码提交；完整统一发布门禁和独立安装一次成功后才发布。任何修正导致冻结源码变动时，保留失败输出并使用新的验收目录。
6. 新功能若不需权威表，schema 保持17，避免无必要迁移；若实现提出新表，先由主 Agent 评估，而非自主扩展迁移。
7. 当前工作区先备份、克隆核对、准确进程检查，再启动已验收新包。部署后只读核对服务版本、静态资源、实际新入口及历史文件/业务记录。
8. 最终报告逐项标注：已实现、实际验证、人工待填、远端待接入。AI/model_not_run、reserved_not_evaluated、原个股阻断及后置 UI 缺陷继续明确保留。
