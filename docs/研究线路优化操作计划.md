## 第一轮目标

使用用户已经确认研究过的《101 Formulaic Alphas》，先取 Alpha #101 原式，在一个明确的数据来源上完成：论文依据 → 数据与时间规则 → 因子计算 → validation 区间统计评估 → 人工判断 → 可复现报告。Alpha #006、跨因子组合和其他论文随后扩展。

首轮验收不要求收益为正。允许得出“缺少必要数据”“无法可靠评估”或“没有观察到稳定关系”，但结论必须与证据、数据和计算产物一致。

代码硬限制：`evaluation.py` 只接受 `data_kind=synthetic`，要求完整 calendar × universe 网格、所有 OHLCV 有限且为正。数据导入验证器还要求合成生成器元数据。真实数据不能通过改标签、补假价格、将停牌收益设零或筛出全期幸存资产来绕过这些限制。

## 操作顺序

### 1. 整理一张研究卡：现在即可进行

我整理已有公式、PDF 第 15 页原文、字段要求、当前实现和独立参考，列出待核对内容。首式保持：

`((close - open) / ((high - low) + .001))`

研究卡分开记录：

- 论文明确给出的公式与出处。
- 本地选择的信号方向、交易时序、样本和评估方法。
- 经济解释及其归因。当前“日内价格压力相对振幅”的解释属于推测，不能写成原文已经证明的机制。
- 未知条件与停止理由；字段替代或公式改动须成为明确的新候选。

用户只需核对实际研究含义和自己的改动，不需要手填 JSON、内部 ID 或摘要。没有实际判断的维度保持“未评定”。

### 2. 确定一个数据来源：实施适配的前置输入

用户提供已有文件路径和来源、可用于本项目的范围；如果没有数据，先选择一个来源，再核实它实际提供的字段和历史语义。不能在来源未定时假设所有 CSV 可通用接入。

我负责盘点文件并形成字段与时间规则表：

- 日期、资产标识、OHLCV 字段及单位；当前引擎即使只算 #101 也要求 OHLCV。
- 市场、交易日历、时区、字段何时可得及是否事后修订。
- 原始/复权价格、公司行动与收益口径。公式中的 `.001` 和价格单位也须记录，不能随转换静默改变。
- 股票池来源、历史成员、上市退市、停牌、零成交量与缺失记录。

缺少历史股票池或公司行动等材料时，明确缩小可支持的研究问题或阻断相关评估；不通过删掉问题资产来掩盖偏差。

### 3. 开发来源专属适配和真实数据验证

流程为：原始只读快照 → 明确字段转换 → 质量与语义检查 → 审阅可执行范围 → 版本化登记。

我实现所选来源的转换和受限真实数据契约，复用现有导入、错误定位、摘要、登记和恢复机制。合成夹具路径保留，真实数据使用独立、可识别的版本。

必须覆盖重复键、缺行、缺值、零成交量、OHLC 异常、非交易日、历史样本变化与公司行动。实现信号可用资格与收益标签可观察资格，保留逐日排除原因；某资产不能被评价时，不能默认为零收益。仅有可观察收益也不代表可以真实成交。

信号截面和组合形成只能使用 t 时已知的成员与字段；t+1/t+2 的标签缺失须单独处理，不能根据未来价格是否完整来回头挑选股票或重排权重。现有 preflight 只核对字段名，下一步还需绑定来源的单位、可得时点及语义版本。

### 4. 在看指标之前固定评估协议

我提出协议草案，用户确认与研究目的相关的取舍：候选、数据范围、信号方向、时间切分、适用样本、基线、预算和停止规则。确实无法从数据说明确认的事项才向用户提问。

当前可复用的时序是：t 日收盘后信号 → t+1 日开盘标签起点 → t+2 日开盘标签终点；信号和两个价格日期均须落在 validation 内。是否适用于所选来源，要先验证。

首轮只做 validation 开发；test 保持隔离。真实行情接入后仍先交付因子统计评估，不把当前毛收益图解释为可成交账户净值。费用、滑点、借券、成交和容量模型未实现；需要净收益研究时另列实施范围。

### 5. 执行并核对计算结果

用户沿用“确认候选 → 运行实验 → 审核结果”入口。我负责让来源适配与现有队列、预算、阶段、失败留痕和报告对接。

先用可手工核对的小样本检查公式、对齐、标签和权重；生产结果与独立参考一致后，再运行冻结的真实数据快照。改变未来数据不得改变过去信号，标签不得跨越 split，失败和缺失不得从统计分母无声消失。

现有独立参考也假定完整正值行情网格；新增真实数据资格规则后，参考必须独立核对资格、标签、排名和权重，不能只放开生产 loader 就沿用原先的通过结论。结果的数据类型、适配器语义、回归兼容契约及报告限制说明同步更新；历史合成实验保持原样。

报告至少保留 Rank IC、有效天数、逐日覆盖和排除原因、当前口径的毛收益、因子值及源数据版本。后续研究诊断可按实际问题增加分期表现、分组关系或换手；新增指标必须有计算定义和独立检查，不先堆图表。

### 6. 依据输出审核并决定下一步

用户在现有审核页查看原文、声明/执行公式、数据规则、图表和可下载结果，实际填写五维判断：引用准确、假设忠于来源、机制归因、字段语义、实现对齐。

- 引用或含义错误：修订研究卡。
- 字段、时间或数据规则错误：修正适配/数据问题，再运行新版本。
- 实现正确但统计结果弱或不稳定：保留结果，记录停止或继续研究理由。
- 输出支持下一步研究：保留候选，按明确理由尝试少量修改，每个修改独立记录。

软件回归批准表示某些预期行为应被保护；不能将“收益很好看”直接当作批准标准，也不能把研究假设改变后的新候选强行与旧契约比较。

### 7. 冻结报告，再做流程效用对照

选择明确的实验生成冻结报告，包含原式/修改的关系、全部尝试、失败、来源条件、指标产物、实际审核和局限。

区分三种对照：

1. 数值对照：生产实现与独立参考/手算，检验计算正确性。
2. 固定流程对照：同一任务和数据下的 `normalized_fixed`，检验执行与复现；相同定义得到相同结果是预期行为。
3. 人工流程对照：CLI/编辑器与工作台完成同一研究任务，记录真实主动时间、等待、返工和完成情况。链路稳定后再测，不作为日常研究前置步骤。当前观测协议仅覆盖单候选 Alpha101，若数据/任务条件改变，先修订并冻结协议。

Alpha101 已用于开发，不能再称为独立保留论文。跨论文泛化需要另一份未参与开发的材料和预先形成的人工判断；最终市场 test 需要单独实现并验证冻结和披露协议。这两项排在首条真实数据研究闭环之后。

## 分工与执行门槛

| 工作包 | 负责人 | 前置条件 | 验收产物 |
|---|---|---|---|
| R1 论文与研究基准 | 研究基准 Agent；用户给实际判断 | 已有 Alpha101，可立即整理 | 研究卡、证据与归因清单、明确未评定项 |
| R2 数据来源适配 | 数据 Agent | 已确定来源与可用文件/文档 | 转换器、语义契约、质量报告、失败样本 |
| R3 评估正确性 | 评估 Agent | 与 R2 先共同冻结字段/样本/时间契约 | 独立参考、边界测试、validation 结果与局限 |
| R4 集成与交付 | 主 Agent | R1/R2/R3 产物可复核 | 基础页面接通、冻结报告、完整验收、备份更新 |

来源确定前只推进 R1 和 R2/R3 的缺口审核；不让多个 Agent 各自猜测数据契约。来源确定后 R2/R3 按文件所有权分开实现，主 Agent 负责共享接口和集成。
