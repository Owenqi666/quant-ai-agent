# v0.22：先看依据，再填写准确结论判断

适用：正式升级到 v0.22.0 / schema17 后的基础工作台。原服务升级前仍沿用已验收版本；源码和专项测试通过不能代表现行服务已经升级。AI 接口和全面 UI 设计继续后置。

## 最短操作

1. 在研究任务中打开已有 **Alpha101 日度任务**或**固定行业组合 MOM 任务**，查看这次实际输出、数据与方法范围。沿用已保存的结论草稿；若没有，先通过现有指标引用入口核对并保存。
2. 在“审核这一次的结论文字”选择具体结论。“本版本原始审核资料”自动绑定此结论的准确版本，点击“打开原论文”，按证据页码和定位核对；行业任务还可阅读固定方法、配置和作者代码。作者代码仅读，不执行。
3. 对照“服务计算的实际值”、证据、候选定义和完整任务输出，分别判断：引用与页码、假设忠实度、经济解释归因、字段含义与替代、实现与声明公式。软件核验摘要和数值引用，不能替你判断原文忠实度或经济解释。
4. 展开“填写本版本的五维判断”，本人明确选择声明来源，填写审核者、实际确认时间、每维判断及理由；先预检，再保存。证据不足可明确保留未知；不为了完成流程全部勾通过。修改已有判断时选择要取代的记录，保留原记录。
5. 查看本版本审核历史和状态，确认保存的是刚刚审核的文字、目标和本人声明。新结论文字需要新的审核；不同人的冲突、未知与取代历史不会合并成软件认定的研究真相。

来源暂不可用时，页面显示原因并保留判断草稿。需要原始依据的维度应暂留未知，待来源修复后再判断。原有五维表单不会因资料 GET 失败被关闭。

## 阅读范围

- **Alpha101**：归档原 PDF、候选定义、实际日度计算结果及指标引用；当前示例数据为合成验证数据。字面公式一致、执行成功不等于真实行情有效。
- **行业 MOM**：归档论文、固定方法与配置、六份作者代码阅读副本、实际行业结果及指标引用。使用 49 行业预计算组合、修订后的历史收益，是 `project_modification`；不是原个股论文复现。候选 gross1/net0 与 long-only 基线 gross1/net1 的净敞口不同，不直接宣称同风险优势。
- 导出和阅读不重新计算实验、不运行作者代码、不读或评价保留区间、不创建人工记录。页面不会预填人工来源、姓名、时间或五维通过值。

有限终点：选择一个准确结论，阅读所有相关依据，按实际判断提交五维声明，再核对准确目标、历史和状态。完整研究质量、人工流程耗时、模型效果仍需要真实人工参与和后续有明确协议的观测；本轮不能自动补齐。

## 可选：只读导出与离线核验

日常评审使用页面即可，无需手填 SHA 或 JSON。以下命令用于技术归档；管理员从当前 `/api/health` 取得工作区身份，并选已有 Claims 与具体 Claim ID。`--expected-target-digest` 可省略，由 GET 自动取得并冻结，不采用任意文件路径打开来源。

```bash
.venv/bin/python -B scripts/prepare_case_review.py prepare \
  --base-url http://127.0.0.1:8765 \
  --workspace-id <health.workspace_id> \
  --claims-id <已保存的research_claims_ID> \
  --claim-id <具体结论ID> \
  --out artifacts/review-materials-my-first-attempt

.venv/bin/python -B scripts/prepare_case_review.py verify \
  artifacts/review-materials-my-first-attempt
```

只发送白名单 GET，不发送审核 POST；拒绝错工作区、过期目标、重定向、来源或历史漂移、超限和链接文件。超时与响应截断允许最多两次显式配置的 GET 重试；请求、文件和总耗时均有上限。输出目录必须全新，已有目录不覆盖。

成功包包含 `invocation.json`、`status.json`、`packet.json`、`manifest.json`、`report.md`、原始来源文件、空白 `blank-judgments.json` 和导出器源码阅读副本。`packet.json` 保留 Case 实际结果 payload、全部同目标审核历史和准确数值；`report.md` 只展示已保存值，不新增计算指标。

GET 或验证失败保存 `invocation.json` 和 `failure.json`，记录失败阶段、错误、可得工作区／目标／材料摘要及接收到的来源摘要；部分写入保留用于排查。失败目录不能通过完整包核验，重试使用另一新目录。无效路径、已存在目录或无法安全写入时，不覆盖原文件。

离线核验确认本地文件摘要、闭合结构、准确引用、实际工具值和空白判断的一致性；来源字节核验与源包所记独立数值参考是不同证据。本地包不能认证原服务器、原始创建收据、完整历史、人员身份或客观研究正确性。源码副本只供阅读，核验使用当前已安装的库，不执行包内代码。无人工记录时保持 pending，无模型调用时保持 model_not_run。
