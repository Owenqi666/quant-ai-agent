# v0.7 人工研究对照：待执行协议

本协议为真实人工使用准备，尚未执行。自动化验收、示例审核和代理生成的文字都不能填成人工观测。项目已提供可重复的软件验证；这次对照回答的是“本人使用工作台是否更容易完成研究任务，以及哪些步骤仍费时或容易出错”。

## 固定任务

使用已确认研究过的《101 Formulaic Alphas》，按 `evaluation_suites/v05/task.json` 的 Alpha101 任务完成一次证据录入、假设归因、候选实现、验证区间计算、审核和报告整理。固定材料、数据和评估配置的 SHA-256 记录在 `evaluation_suites/v07/human_protocol.json`。

这是一个已熟悉的开发任务，不是独立保留论文，也不用于证明市场收益。五日均值等新增修改式不加入本轮比较，避免两条路径的工作范围不同。最终市场 test 区间保持隔离。计算统一使用同一版本的现有引擎和规范化固定模式；AI、RAG、自动联网检索均未启用。

## 两条比较路径

| 路径 | 操作范围 | 共同交付 |
|---|---|---|
| manual_cli | 用文本编辑器手动组织任务，调用现有 CLI，手动整理证据与结果索引 | 输入来源、任务/版本、实验路径、核验结果、五维判断与理由、报告路径 |
| workbench | 使用基础研究表单、后台实验、审核及报告入口 | 相同材料、表达式、数据和指标；相同五维审核与输出记录 |

两条路径都可以使用同一份字段和算子文档。工作台路径允许其现有模板；需记录哪些内容直接复用了模板。不得把手动路径故意设成缺少必要文档或禁用正常工具。人工应自行核对所有解释；模板不会成为正确答案。

正式开始前，在本地工作目录复制协议和两份观测模板，填 participant、协议版本、实际代码 commit、机器环境、允许工具、顺序和停止条件。建议先做一次不计入对照的熟悉性试用，然后按预先记录的顺序执行。若重复使用同一任务，注明学习效应；只有一人一任务时只报告个案。

## 时间与过程记录

按 reading、hypothesis、implementation、run_setup、review、report 六个阶段记录真实开始和结束时间。人工主动工作、等待工具、主动离开分别保存，不根据问题创建到关闭的历时推算人工时间。

现有工作台计时仅覆盖审核阶段；其余阶段通过观测模板手动记录明确区间。将审核区间复制进总记录时保留 review ID 和来源，不再次叠加同一时间。跨阶段或跨记录重叠需说明并合并，不能双重计时。关闭页面/程序前未结束的区间标为 interrupted；不补填记忆中的结束时间，耗时保持缺失。

保存遇到的错误、返工内容、修改理由、求助和使用模板的情况。未完成和放弃的任务也保留记录。任何影响数据、假设、表达式或评价范围的改动都应停止原对照并另建协议版本，不能只修改较慢路径的条件。

## 完成与评价

一次任务完成要求：引文有可核对的页码；原式与经济解释归因明确；候选通过合法性检查并产生可验证结果；报告数字对应实际产物；五维审核各有实际判断和理由。审核可以指出假设或解释不成立，不要求为了“完成”把五维全部标为通过。

只在实际填写后计算：任务完成情况、错误/返工分类、实测主动时间与等待时间。始终保留原始观测、分母、未测量字段和未完成原因。流程耗时以真实区间为依据，不从自动化 HTTP/E2E 日志推导。小样本直接呈现每条记录；不预设工作台更快，不从同一任务的重复测量推断普遍提升。

`human_observation_template.json` 中的 null 和空数组都表示未观测。它不是已完成记录，不会自动导入系统、增加人工覆盖率或批准回归用例。参与者可以先完成一次工作台试用和真实审核，之后再决定是否值得做更大范围对照。

## 后续材料

扩展前先选择一个未参与当前实现迭代的研究任务，冻结人工预期和证据，再运行流程。来自同一个 Alpha101 原式的窗口变体仍属于同一研究来源。获得真实数据后需新协议明确数据语义，不能把合成数据的结论直接迁移过去。
