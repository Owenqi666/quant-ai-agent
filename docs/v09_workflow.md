# v0.9：从真实流程记录到可核验的观测回流

## 启动与升级

沿用 README 安装命令，构建前端后启动：

```sh
.venv/bin/python -m paper_alpha.server.launcher --home var/my-v09-workspace --port 8766
```

这是独立工作区。已有工作区迁移到 schema 7 前，停止其 API/worker，按 `docs/backup_restore.md` 离线备份并恢复到新目录，再用新代码启动新目录。保存旧目录与备份；不要让新旧版本同时写入同一个数据库。v0.9 支持 schema 1–6 顺序迁移，迁移不会生成历史人工观测。

## 本人使用步骤

1. 先阅读 `docs/v07_human_evaluation.md` 的同任务两路径协议。它是熟悉的 Alpha101 合成任务开发案例，尚未实际执行，也不是独立保留论文或市场收益评测。
2. 本轮协议固定 `evaluation_suites/v05/task.json` 的单个 Alpha101 候选、证据、假设、预算及区间。工作台默认多候选示例不是这份单候选任务。按该文件建立/复制研究并在高级任务入口仅填写 evidence、hypotheses、candidates、evaluation、budget；论文与数据选择已有 Alpha101 的同一版本。标题可以自定。其他科学条件变化会被拒绝，需另行设计新协议。
3. 明确参与者、环境、实际代码 commit、允许工具、顺序、熟悉程度及停止条件。熟悉性试用声明 practice_session，不能混入正式对照。
4. 按 reading、hypothesis、implementation、run_setup、review、report 记录真实主动、等待或离开区间。未测量就保留缺失；未完成和放弃也记录。当前只有审核有内置计时器，其余阶段仍需实际手记，导入器不会推算。
5. 在「流程观测」下载当前空白 JSON 模板并填写。该模板是导入 schema 1 的显式结构，旧 v07 空白模板保留原样；不直接把旧 null/空数组视为观测。文件中的 record_status 只有在实际记录后才改为 observed。
6. workbench 路径绑定确切修订、运行、尝试及本人的结构化审核；完整记录的五维判断必须与绑定审核相符。复制审核区间时填写 source_reference=review_id，时间只计一次。详情中的原始 JSON/实验记录可核对 ID。manual_cli 路径记录外部引用，服务不会打开任意本机路径或声称外部产物已核验。
7. 上传文件或粘贴 JSON，明确选择「本人实际观测」或「自动化验收样例」，与 JSON source 保持一致。预检后核对覆盖、限制和绑定，再勾选确认不可变保存。修改任意输入都要重新预检。
8. 保存后查看历史与服务端汇总，导出原记录。只有满足明确相同声明条件、两路径各一条完成非练习人工记录且六阶段主动区间完整时，才计算个案时间差；缺失与不兼容显示原因。分母、失败/放弃、返工文字条数以及原区间都保留。

记录来源、环境及人工时间属于声明。report_reference 是声明引用，不核验其所指报告；outputs_verified 只表示绑定实验快照的核验。当前不校验运行/审核创建时间与声明观测会话的先后，不能据此认证观测真实性。六阶段都有区间也不等于连续全程无漏记；对照不能推断普遍效率改善。当前不提供记录覆写或自动纠错，提交前必须核对；不能用新的 session_id 把同一次观测重复计为新样本。

## 提交中断与恢复

提交前将原请求和去重标识保存到本浏览器。响应未知时刷新，仍在同工作区/研究下以原请求安全重试。保存成功但列表刷新失败时，保存结果仍有效，可单独刷新历史。草稿恢复和请求确认分开；清空浏览器存储会丢失本机恢复入口，服务器原记录仍保留。

409 可能表示原提交或观测身份冲突，因此当前保守保留固定请求供核对，不自动更换键或解除。该限制不产生重复记录，但跨窗口同时导入同一观测时需要核对服务器历史。当前仍按单编辑窗口使用。

## 可复现的工程示例

```sh
.venv/bin/python scripts/demo_v09.py --out artifacts/my-v09-observation-example
```

必须使用新目录。脚本建立临时 API/worker 和合成工作区，保存两条 automation 记录：外部引用且部分计时的未完成记录，以及绑定真实引擎产物、尝试与自动化结构化审核的记录。验证提交后断流、四路并发原键确认、冲突拒绝、审核计时不重复、人工分母为零、导出字节冻结、离线备份与新目录恢复。所有虚构时间只用来验证算术，不是人工耗时。HTTP trace、请求、冻结导出和 delivery.json 均留存，退出关闭自建服务。

## 后续三个阶段

- 数据适配准备：`scripts/check_research_readiness.py` 检查来源、声明、字段/时间约定与快照摘要。具体来源的真实适配器尚未实现；现有计算仍为 synthetic-only。
- 独立研究准备：冻结新材料和人工预期，区分独立研究内容与允许复用的上下文。准入检查不能证明材料从未被看过，也没有扩充现有七公式参考的声明范围。
- 最终测试：先按 `docs/v09_final_test_protocol.md` 冻结研究协议，再实施受控最终评测入口；本轮没有开放 test。

完整计划见 `docs/v0.9任务清单与Agent分工.md`。实际本人观测、真实数据、独立材料和远端 CI 的外部证据仍单独列为待完成，不由软件测试代替。
